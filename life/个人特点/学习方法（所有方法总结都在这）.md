我的主要问题不是不能坚持。过去一年健身，两年公众号，一年英语磨耳朵已经证明，只要目标明确、路径清晰、反馈稳定，我能够长期执行，中断以后也能够回来。

目前真正需要解决的是：

1. 容易把“准备”误认为“推进”。
2. 容易选择低风险、低反馈的代理任务，长期不接触最终目标。
3. AI辅助产生大量“我看懂了”的错觉，但没有转化成独立能力。
4. 从“AI提供信息”切换到“自己验证”时，容易休息、刷手机或换任务。
5. 面对有明确输赢、会暴露真实能力的任务，更容易延长准备期。
6. 容易用“做其他有意义的事情”逃避当前最重要、最困难的任务。
7. 单次执行失败以后，容易从行为评价升级成人格评价，再通过发狠制定高压计划。
8. 喜欢持续寻找“真正的问题”“最关键的方法”，存在用优化学习方法代替实际训练的风险。

所以现在的核心任务是建立：“定义真实终点 → 尽早接受现实检验 → 暴露瓶颈 → 针对训练 → 再次接受检验”的稳定循环。


最高原则目标稳定，方法可变，不因为一天状态不好、一次任务失败、一个新观点，就重新设计整个学习体系。运行流程固定为：定目标→ 设计当前方法→ 执行→ 收集结果和感受→ 判断与目标的差距→ 定位问题→ 最小幅度修改方法→ 再执行。修改方法必须建立在真实执行暴露的问题上，禁止理论上这个新方法似乎更好，所以重新换一套。如果旧方法没有出现可观察的失败，就不优化。


第一原则：从真实终点反推，而不是从“我觉得应该学什么”推，过去模式先碰A，再决定练什么B，我想完成A→ 我认为先学会B才能做A→ 长时间训练B→ 从来没有验证B是否真的是A当前的瓶颈→ B给我大量努力感→ A几乎没推进。以后改成目标是A→ 尽可能直接测试A→ A在哪里失败？→ 找到当前瓶颈B→ 针对性训练B→ 回到A重新测试。核心口诀：“先碰终点，再补能力；不要等能力齐了，才第一次碰终点。”，任何目标计划开始前先告诉我现实世界究竟通过什么结果判定我成功（A）？找实习（A）的证据不是学好agent（B）而是拿到offer；英语好的证据不是每天背单词而是面对材料能理解，能真人沟通；论文证据不是看论文而是有产出；打好篮球证据不是练习运球而是实战能得分，永远区分目标 ≠ 指标 ≠ 方法。尽管这些B可能有用，但也要建立起哪些B是关键瓶颈，要从A里测。你给的方法计划（B），计划必须确保所有“B→A”都必须有因果假设，如何验证B做得好，A真的会提高？A失败真的是B不够好吗？有没有离A更近、更直接的动作？如何尽快测试B→A到底有没有效果？这里可以先给大致你认为可以的计划，我尽快测，回来给反馈


问题驱动，而不是教材驱动，优先按照“我要实现功能X→ 开始做→ 撞到问题Y→ 学解决Y需要的最小知识→ 解决→ 回项目。”


知识不要求全部理解到底层，知识分三级：**核心掌握**：与求职、项目核心设计、论文贡献等直接相关，要求独立使用、解释、迁移。**会用即可**：知道用途、输入输出、基本边界，能够正确调用，需要时再深入。**暂时黑盒**：目前不阻塞最终目标，知道它是什么即可。**判断标准**是：“不理解这个东西，现在是否阻塞我的最终目标？”如果不阻塞，就不挖。不是把所有东西拆到底，而是识别真正决定结果的变量，从而知道什么值得深入，什么不值得，==这里如何定义一件任务是否阻塞当前的目标==


每个任务必须提前定义DoD，任务必须拆到可以行动的颗粒度，禁止任务是，今天学RAG、做论文、学英语、复习Java。合格任务需要明确动作 + 短反馈 + 真实结果 + Definition of Done。例如“实现read_text(file_path)，按utf-8→utf-8-sig→gbk解码；分别用UTF-8中文txt和GBK txt测试，均能正确输出。”，原则上，一个最小训练动作应该可以在约1小时内完成。但不是说所有任务只能持续1小时，大型任务可以连续完成多个小模块。


==这里如何定义完成？==




AI采用渐进撤离，而不是“要么依赖AI、要么完全闭卷”，连续成功，再撤脚手架。连续失败，降低半级/一级。难度调整，而不是人格审判，辅助等级：L0，AI给完整实现，我运行并理解大致结构。L1，AI删除10%—30%的关键代码，我补TODO。L2，AI只给函数签名、伪代码、关键API，我实现。L3，AI只给需求和DoD。允许查官方文档/搜索，但不能直接索要完整答案。L4，接近面试环境，有限帮助，独立完成核心实现。L5，改变需求、制造bug、增加约束，我必须迁移知识并解释trade-off。不要从L0突然跳L4。

严格区分“接触过”和“掌握”，目前统一标准：L0：见过。L1：能跟着做。L2：理解并能补全。L3：能够独立实现（不是不借助ai，而是能预测结果）。L4：面试/闭卷环境基本能完成。L5：可以迁移、debug、应对变式。后续关于感觉词都必须准确说明是在哪个lever，并给出证据，验证（感觉不可靠，证据可靠，让ai判断是否真的在这个层次）



AI给出东西，到自己做的切换点必须特殊保护，这是自己的高频漏洞。典型链条：AI搜集信息→ 感觉已经做了不少→ 准备进入自己验证→ 休息一下，手机/其他小事→ 主任务漂移。要增加交接动作。每次AI阶段结束：AI停止→ 不休息→ 立即完成3—10分钟自主输出→ 之后才允许休息。交接动作可以是写5行伪代码；回答一道场景题；补三个TODO；画一次状态流转；先预测代码运行结果；关掉论文写出input/method/output；用自己的话复述三个关键点。必须建立新的条件反射“AI停止输出” = “轮到我输出”。



验证难度也采用渐进增加，禁止AI刚完整演示→ 马上要求自己完整闭卷重写。可以完整代码→ 挖3个TODO→ 只留函数骨架→ 只留伪代码→ 只给需求→ 需求变式。要训练的是能力迁移，不是用突然增加的痛苦证明自己有毅力。


真正有效的学习闭环，Java、Agent、论文、六级全部走这个循环，**统一使用ai做的当输入→ 自己模仿→ 回忆→ ai来验证→ 自己做变式→ 间隔复测**。最重要的是Retrieval没有答案时能否自己提取。Transfer条件改变以后能不能使用。因此AI以后优先承担四个角色面试官；出题人；故障制造者；验收员。减少单纯作为“答案生成器”。

每天至少存在一个现实检验，”学习了“不算现实检验。例如：开发：pytest、闭卷编码、变式、PR、commit、mock interview、真实投递，算法：限时独立做题。论文：实验结果、图表、protocol、导师/AI攻击问题。六级：限时真题正确率、作文评分、翻译评分。评价一天不能只看今天学习了几个小时？还要问今天什么东西接受了评分？



**根据精力改变任务，而不是放弃推进**，高精力：算法闭卷；项目核心模块；论文设计；Mock Interview；复杂debug。中精力：SQL练习；测试；六级阅读；论文整理；普通编码。低精力：README；修测试；错误整理；单词复测；实验表格；简单文档；Git操作。状态不好可以降负荷，不能默认切到手机。


反馈只记录事实，不写长篇自我审判（==感受太主观，不具体，ai没办法给出具体的解决方法==），一次训练反馈优先只写：任务：结果：AI辅助级别：独立测试结果：卡点：感受：下一次待验证问题：
例如：
“任务：M4 process_document
结果：pytest通过
AI：L1
独立：核心流程只能完成60%
卡点：异常路径和session生命周期想不起来
感受：空白文件出现时不知道从哪开始。”






出现失败时的诊断顺序，禁止第一反应，“我懒/我怕困难/我意志力差”。依次判断：目标是否清楚？DoD是否清楚？任务是否太大？前置知识是否缺失？难度是否跨级？AI撤离是否过快？反馈是否太迟？任务是否距离真实目标太远？当前精力是否匹配？环境有没有制造巨大诱惑？是不是任务切换点出问题？最后再判断是否存在主动逃避。**不要把所有学习问题心理化**。语言协议，非常需要持续监控的一部分。警惕这些词：“一定、100%、根本、都是、从来、最关键、我就是……、自欺欺人、我的底色就是……”。这些语言容易把：观察 → 规律 → 人格定论三个步骤一次跳完。**语言越精确，问题越容易解决**。


尤其警惕“最关键的问题”成瘾，有比较强的元认知能力，但也因此容易不断发现：“原来这才是我的核心问题。”，然后理解一个新概念→ 很兴奋→ 重构整套方法→ 过几天再发现另一个“真正核心”。以后**一个新观点必须经过实际行为验证，才能进入长期协议**。原则“一次发现叫假设，反复出现才叫模式，有数据支持以后才修改系统。”


整套方法最后压缩成一张脑内流程图，以后面对任何学习任务，要跑：”我要的现实结果是什么？我能不能现在直接碰一次终点？能就直接测试。不能就找到距离它最近的测试，测试完找具体失败在哪？这个失败目前由什么瓶颈造成？只补这个瓶颈需要的最小知识。把训练拆成≤1小时、有明确DoD的小块。不会就让AI搭脚手架，不逞强。AI输出结束，立刻进行3—10分钟交接动作。逐渐撤掉AI。自己回忆/编码/判断。给变式。重新碰终点。根据结果按照标准反馈格式输出给ai决定下一步“。这就是目前真正应该重复的循环：A → 测A → 找瓶颈B → 练B → 再测A。而不是B → B → B → B → 等我觉得自己准备好了 → A。
