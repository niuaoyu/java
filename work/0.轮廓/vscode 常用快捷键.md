### 看代码的“前后左右”

| 操作          | 快捷键 (Win/Linux) | 快捷键 (Mac)          | 用途                                                |
| ----------- | --------------- | ------------------ | ------------------------------------------------- |
| **跳转到定义**   | `F12`           | `F12`              | 跳到函数/类的定义处。**读代码最核心的操作**。                         |
| **跳转到引用**   | `Shift + F12`   | `Shift + F12`      | 查看**“谁调用了这个函数”**。你想知道 `build_registry` 被谁用了，就用这个。 |
| **返回上一位置**  | `Alt + ←`       | `Ctrl + -`         | **神键！** 看完定义后按它，直接跳回你刚才读代码的地方。                    |
| **前进到下一位置** | `Alt + →`       | `Ctrl + Shift + -` | 与上面相反，用于“反悔”后退操作。                                 |


### 全局搜索——用关键词“大海捞针”

当你只知道一个函数名、类名或变量名（比如你之前问的 `attempt.completed`），但不知道它在哪时：

| 操作 | 快捷键 (Win/Linux) | 快捷键 (Mac) | 用途 |
| :--- | :--- | :--- | :--- |
| **全局搜索** | `Ctrl + Shift + F` | `Cmd + Shift + F` | 在**整个项目**里搜索文本（支持正则）。看到 `emit` 或 `publish` 就是发射点。 |
| **搜索符号 (Symbol)** | `Ctrl + T` | `Cmd + T` | 输入 `#attempt` 或 `@execute`，直接搜索所有**类名、函数名**，跳过注释和字符串。 |
| **文件内搜索** | `Ctrl + F` | `Cmd + F` | 只在当前打开的文件里搜索。 |

> **心法**：找“发射点”用全局搜索（搜事件名），找“函数定义”用符号搜索（`Ctrl+T`）。

| 操作 | 快捷键 (Win/Linux) | 快捷键 (Mac) | 用途 |
| :--- | :--- | :--- | :--- |
| **快速打开文件** | `Ctrl + P` | `Cmd + P` | 输入文件名（比如 `session_service.py`），回车打开。**不用去点鼠标找文件树**。 |
| **打开/关闭侧边栏** | `Ctrl + B` | `Cmd + B` | 快速隐藏文件目录树，让编辑区更大，专心读代码。 |
| **在侧边栏中定位** | - | - | 在编辑器里右键点击文件标签 → **在侧边栏中显示 (Reveal in Explorer)**。 |

### 🔬 第四步：看结构——“鸟瞰”当前文件

当你打开一个几百行的文件（比如 `agent_loop.py`），想快速了解它里面有哪些函数、类，而不是从头滚动到尾：

| 操作 | 快捷键 (Win/Linux) | 快捷键 (Mac) | 用途 |
| :--- | :--- | :--- | :--- |
| **打开大纲** | `Ctrl + Shift + O` | `Cmd + Shift + O` | 在文件顶部弹出一个下拉框，列出该文件所有的**函数、类、变量**。输入 `@` 可快速筛选。 |
| **折叠代码块** | `Ctrl + Shift + [` / `]` | `Cmd + Option + [` / `]` | 把大段函数折叠起来，只留函数名，像看目录一样扫读。 |

### 🧠 第五步：进阶心法——用“业务关键词”而非“代码变量”去搜索

这是从“新手”到“老手”的重要区别。**不要只搜代码里的变量名，要搜业务概念。**

| 搜什么 | 怎么搜 | 为什么有效 |
| :--- | :--- | :--- |
| **业务术语** | 直接搜中文或英文业务词 | 比如你想找“回测逻辑”，不必搜 `def run_backtest`，直接搜 `"backtest"` 或 `"回测"`，因为开发者在写日志或注释时一定会提到这个词。 |
| **错误信息** | 搜 `"timeout"` 或 `"failed to connect"` | 比搜 `Exception` 更精确，直接定位到报错逻辑的位置。 |
| **API 路由** | 搜 `"/sessions"` 或 `"@app.post"` | 快速找到**对外暴露的接口**（Controller 层），从入口往下读，比从深层的工具类往上找要容易理解。 |

---

### 📝 总结：读一个复杂项目的“三步连招”

1. **定位入口**：先搜 `@app.post` 或 `/sessions` 或 `main` 函数，找到请求的**入口文件**。
2. **画流程图**：用 `F12` 跟进去，一个函数一个函数地跳，看到 `Registry`、`Service` 这种大面积调用的，用 `Shift + F12` 看引用。用纸笔或脑图记录调用顺序。
3. **断点调试**：在关键行（比如 `attempt.created` 的 `emit` 处）按 `F9` 打红点，启动调试（`F5`），**跑一遍业务流**。观察变量变化，比纯静态看代码效率高 10 倍。
