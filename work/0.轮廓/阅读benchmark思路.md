
目标是：“得到可信的 ONet benchmark 结果并且能够修改 ONet。”，核心动作，”不是为了看懂而看代码，只在一个未知问题阻碍实验时阅读足够的代码来消除这个未知。“

终点不是“跑通 benchmark”，而是建立一条论文论证链，最终论文需要回答的，本质上是：

研究问题
→ 为什么值得研究
→ 现有方法怎么解决
→ 它们在你的临床条件下有什么问题
→ 你提出什么假设/改进
→ 怎么公平实验
→ 得到了什么结果
→ 为什么出现这个结果
→ 能支持什么结论。

以后判断一个东西该不该学，只问：“为了让我能解释实验设计、实验结果或者修改方法，我需要把它理解到什么程度？”

## 两条贯穿规则

1. 打开任何源码前，先写一句：「我打开它是为了回答 ______」
2. 停止规则：不理解 → 它影响当前实验/论文结论吗？不影响 → 标记未知继续；影响 → 读到足以做正确实验；马上要改 → 深入实现


不理解是因为缺少概念，先学概念再来看实例（代码）代码不是你知识产生的起点。代码是你验证：“论文概念在这个 benchmark 里到底是怎么落地的。”

1. 问题图：必须能不用任何术语解释清楚，我手里有什么（稀疏临床切面/轮廓）？我想要得到什么（完整的LV/RV三维结构）？中间的困难是什么（稀疏，不完整.....）？最终这个benchmark在问什么（不同三维重建方法，在不同稀疏程度的输入下，性能怎么样，哪些更好）？这是地基
2. 方法图：先画onet，禁止出现代码文件名，要理解，稀疏轮廓怎么encoder后得到心脏表示的z，z+查询点x怎么decoder得到x是否属于lv/rv的？训练时预测的occupancy和真实的occupancy怎么计算loss得到学习参数的？推理时，3d空间很多查询点x怎么得到occupancy field然后抽取等值面得到lv/rv的mesh？任何词的不了解都要查，这不是代码，是论文概念
3. 实验图：训练mnms2，选模型参数，得到报告，每个测试集再通过十个指标full/sax/saxtrim得到预测值prediction和gt计算几何指标和结构指标

单样本数据流阅读，追踪一个真实数据对象的生命周期，核心原则别跟函数走，跟数据走

第一阶段：只看这个数据，磁盘找到文件，被哪个代码找到？被谁加载？加载后的东西是什么？做了什么预处理？进入dataset后是什么？被DataLoader拼成什么？EncoderDecoder做了什么？预测结果维度是什么？和gt比什么？
1. 认识初始数据：亲眼看到数据的维度，写个脚本，print或者可视化，因为此时数据不是变量名而是真实数坐标，有直观感受
2. 第一趟：只读磁盘数据怎么到sample的？目标只有一个：“这个真实 NPZ 怎么变成 Dataset 返回的一个 sample？”，可以打断点！可以让 AI 帮你临时加入一个统一的观察函数，这就知道如何从真实的磁盘数据，读进来，变换后得到的单样本dict的，**过程当中除非不得不，比如要知道数据怎么变化的，不然不要研究包，只研究主线路，包只要知道输入输出维度即可**
