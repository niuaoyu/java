
用print的弊端，当需要删除或保留部分print语句时，需要逐个文件搜索（如使用Ctrl+Shift+R），工作量非常大。管理不便，无法统一控制日志级别，难以区分调试日志和正式日志。同时功能局限，缺少时间戳、日志级别、调用位置等关键信息

日志管理的重要性
	调试需求：需要记录输入参数、输出结果、异常信息等关键调试信息
	异常追踪：通过try-catch捕获异常后必须记录错误日志
	统一管理：可以集中控制日志格式、输出位置和日志级别

loguru好处
	单一logger：整个应用只需使用一个预配置的logger对象
	简化API：无需处理Handler、Formatter、Filter等复杂概念
	灵活输出：通过add()函数可以轻松配置多种输出方式（控制台、文件等）
	自动上下文：自动记录调用模块、函数名和行号等信息


实际应用场景：在FastAPI处理多请求时，原生日志无法区分不同请求的日志流，只能知道问题出现在哪，不知道问题是哪个请求造成的

解决方案：
	通过中间件为每个请求生成唯一request_id
	使用logger.bind(request_id=request_id)绑定上下文
	日志格式中包含{extra[request_id]}字段实现请求级日志追踪
	对比优势：相比原生logging模块，减少70%以上的样板代码量
