解决办法：通过精心设计的提示词提供上下文信息，包括相关字段、表信息、主外键关系和指标计算规则

这个本质还是上下文不足，就像现在的skills，其实这个项目现在也过时了，因为skills能解决这个重复性的工作，只需要把表分门别类归置好，直接调用，现在是要练习怎么做！

这个功能以后一定不存在，ai的发展，这种常见的需求一定有办法解决，但现在还需要定制化





Logstash = **数据版的“保洁阿姨”**，把乱七八糟的数据打扫干净、摆整齐
Kafka = **系统间的“缓冲隔离带”**，让上下游解耦，谁挂都不影响谁。


**日志处理流水线**：
服务器日志 → Logstash（采集+清洗） → Kafka（缓冲） → Logstash（消费） → Elasticsearch（存储+搜索）


实现：基于元数据知识库（MySQL+Odrant+ES）、多路召回相关表字段、大模型生成可验证SQL

固定的12步骤：
```
抽取关键词
召回字段信息
召回指标信息
召回字段值
合并召回信息
筛选指标信息
筛选表信息
添加上下文信息
生成SQL
验证SQL语句
执行SQL语句
```
