Logstash = **数据版的“保洁阿姨”**，把乱七八糟的数据打扫干净、摆整齐
Kafka = **系统间的“缓冲隔离带”**，让上下游解耦，谁挂都不影响谁。


**日志处理流水线**：
服务器日志 → Logstash（采集+清洗） → Kafka（缓冲） → Logstash（消费） → Elasticsearch（存储+搜索）


实现：基于元数据知识库（MySQL+Odrant+ES）、多路召回相关表字段、大模型生成可验证SQL

固定的12步骤：
```
抽取关键词
召回字段信息
召回指标信息
召回字段值
合并召回信息
筛选指标信息
筛选表信息
添加上下文信息
生成SQL
验证SQL语句
执行SQL语句
```

业务库与数据仓库区别：
	业务库：支撑日常交易和操作（"干活"）
	数据仓库：支撑分析和决策（"复盘"）


## **数据仓库**

模型设计：
1. 事实表(fact_order)：存储核心业务交易数据
2. 维度表(dim_region等)：存储描述性信息

分析灵活，支持多维度组合分析
性能优化，维度表数据量小，事实表结构简单
扩展灵活，新增维度只需添加维度表，不影响现有结构

把维度表可以理解为索引，而事实表是具体数据库的数据，索引可以随意组合来查数据


## **元数据知识库**

作为数据仓库的"说明书中心"，统一管理表结构、字段定义、字段取值示例及复杂指标说明，支持智能检索与SQL生成

作用是类似一个md文档，说明有多少个表，表叫啥


## **agent实现**

上下文信息注入：
语义相近的字段信息
相关表信息（通过字段与表的一对多关系确定）
主外键关系（防止大模型随意关联字段）
指标计算规则（特定领域的专业计算逻辑）
字段取值（通过全文检索匹配自然语言描述与实际值）
技术实现：
使用全文检索将自然语言描述转换为数据库实际值
所有字段取值存入ES索引库
通过向量检索找到最相关的元数据
