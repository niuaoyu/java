
简历上的 Agent 项目，要回答面试官的四个问题：

1. **它解决什么问题？**（明确的场景与任务定义）一句话说清这个 Agent 为谁、解决什么任务、输入输出是什么，toy 项目最常见的问题就是“什么都做一点”。面试官第一问就是“它到底干嘛的”。比如写：”面向 XX 场景的 Agent，输入 XX，输出 XX，支持 XX 类任务“。为什么这个场景需要 Agent，不用单次 LLM？任务边界在哪？哪些不做？要能一句话说清，且能说出“为什么需要多步/多工具”。
2. **它怎么工作的？**（Agent 架构与决策循环）
	1. Agent 的核心循环——感知、规划、调用工具、观察、再决策，直到完成或终止，这是 Agent 区别于普通 RAG/LLM 的根本。没有循环，就是单次调用，要写清楚决策范式：ReAct / Plan-and-Execute / 多 Agent 协作、最大步数限制、终止条件，简历上要体现，基于 ReAct 实现多工具决策循环，最大步数限制 8，支持提前终止，可能会遇到的面试问题，为什么选 ReAct 不选 Plan-and-Execute？死循环怎么防？步数上限怎么定的？合格标准是能画出循环图，说清每一步输入输出
	2. 工具层（Tool Use），agent调用外部的能力，比如搜索、计算、数据库、API，没有工具就没有agent，写清楚，有几个工具，各自职责，工具描述怎么写的（影响选择准确率），参数校验、schema 定义，简历上要体现出类似，”集成搜索、计算、数据库查询 3 类工具，用 JSON Schema 约束参数，工具选择准确率 89%“，面试可能会被问，工具多了选择会不会变差？工具调用失败怎么办？参数错了怎么处理？合格标准是能说清每个工具的输入输出，以及工具描述怎么影响选择
	3. 记忆上下文，Agent 在多轮/多步中怎么记住历史、管理上下文长度，步数一多，上下文爆炸，成本上升，还会丢关键信息。写清楚短期记忆，长期记忆，压缩策略，简历上要体现出具体的数据，”设计上下文压缩策略，多步任务 token 消耗下降 35%，关键信息保留率 92%“，面试被问，”压缩会不会丢信息？怎么判断哪些该留？长期记忆怎么检索？“，要说得清楚上下文什么时候会爆，你怎么处理的
	4. 
3. **你怎么知道它好？**（评测最关键），用标注数据 + 指标，量化 Agent 的表现。没有评测，所有“效果好”都是空话。这是 toy 和简历项目的分水岭。要写清楚评测集，多少条，怎么标的。关键的指标比如任务完成率、工具选择准确率、Recall@K、平均步数、token 成本、失败率，以及baseline是什么（跟什么比）？简历上写类似，”构建 30 条标注评测集，任务完成率 74%→91%，平均步数 4.2→2.8。“，面试会被问， “评测集怎么标的？谁标的？30 条够吗？指标为什么选这个？baseline 公平吗？”，要有真实数字，能说清标注规则，承认规模局限。
4. **失败处理与鲁棒性**？真实环境一定出错。只跑 happy path 是 toy，工具要有失败、格式错、检索空、超时、死循环时的应对。写清楚，重试策略（几次、退避、幂等）、降级策略（换工具、兜底回答）、格式校验与修复、熔断与超时，同样简历上也要体现数据，“设计工具失败重试与降级，端到端失败率 22%→6%”。面试会被问，“重试会不会重复副作用？写操作怎么保证幂等？降级后质量怎么保证？”，同样要能说清每类失败的应对，且知道副作用边界。
5. **可观测性与成本？** 不能测量就不能优化。面试官爱问“你怎么知道慢在哪”。要有日志、追踪、token 消耗、延迟统计。写清楚每次调用记录什么（步数、工具、token、延迟）、延迟 P50/P95、成本估算，简历上体现数据，“ 引入调用链日志与成本统计，P95 延迟 8.4s→3.1s，token 成本降 35%”，面试被问，“延迟瓶颈在哪？缓存怎么设计的？怎么失效？成本怎么算的？”，要能够能定位瓶颈，能说清优化前后的数字来源
6. **它哪里不行？**（边界与取舍，决定深度）面试官靠这个判断你是“真做过”还是“照着教程跑”，你做了什么妥协，为什么，什么情况下不适用。写清楚方案对比，Agent vs 单轮 RAG vs 纯 LLM，对应的代价（延迟、成本、复杂度换来了什么）是什么？什么适合，什么不适合？简历上体现数据，“ 对比纯 LLM / 单轮 RAG / Agent，Agent 完成率高 18% 但延迟高 2.3 倍，据此给出适用场景建议”，要能被问， “那到底该不该用 Agent？什么场景你会放弃 Agent？重来一次你会怎么改？”，能说出代价，给出选型建议，不吹全能

把这些串成简历 bullet
> **多工具 ReAct Agent（个人项目）**
> - 面向 XX 场景，基于 ReAct 实现多工具决策循环，最大步数 8，集成搜索/计算/数据库 3 类工具
> - 构建 30 条标注评测集，工具选择准确率 68%→89%，任务完成率 74%→91%
> - 设计失败重试与降级，端到端失败率 22%→6%
> - 上下文压缩 + 语义缓存，P95 延迟 8.4s→3.1s，token 成本降 35%
> - 对比纯 LLM / 单轮 RAG / Agent，输出适用场景与成本取舍

如果面试官问“你怎么知道它好”“它哪里不行”“为什么这么做”，你都能答上来，就是合格项目。反过来：**只能演示、不能量化、不能讲取舍的，就是 toy。**
