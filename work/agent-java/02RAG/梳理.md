什么是RAG？检索增强生成，问一个本地知识库，llm不知道，乱说，塞答案与问题给llm，但如果答案太大，涉及上下文过大问题（尽管现在都百万上亿token的上下文，会面临贵，且幻觉问题），于是把问题切块，同时建立问题和切块的答案相似程度，按需注入上下文。

rag流程就俩，建立向量，检索向量
1. 建立向量：把md、pdf数据，切片（怎么切的准？），分成若干个chunk，计算向量值，得到向量，存到向量数据库
2. 检索向量：提出的问题，计算向量值得到向量，与向量数据库对比相似度（一般有三个方法，余弦相似度cos，欧氏距离l2，点积，这三个都是粗排序，后续还有混合排序，和rerank，==检测rag好与不好就在这了==），相似度相近的，拿到数据和问题，传进llm的上下文

有一些步骤让问题跟存的向量尽量找的准，比如，在存的时候把文件名item_name也存下去，如果有问题问的刚好跟name类似，就可以筛掉一部分内容，可以在更小的范围内做向量数据库相似度查询，也有取舍，舍去的可能也需要呢？怎么办？
