
TestClient 和 uvicorn 的差异，本质是「同步调用」和「异步网络」的差异：

uvicorn：真实网络，响应发送后客户端的同时，服务器继续跑任务。「发送响应」和「执行任务」并行。服务员告诉你「菜已下单」（响应），然后厨房慢慢做（后台任务）。你先拿到「已下单」的确认，菜好了再上。

TestClient：进程内同步调用，await app(...) 等 app 完全返回，服务器处理完所有事才发送响应。「发送响应」和「执行任务」串行。服务员说「我去厨房看看」，然后等到菜做好才回来告诉你「菜好了」（响应）。你等了整个做菜时间。

TestClient 的本质不是真的网络客户端。 它不通过 TCP 连接服务器，而是直接在进程内调用 ASGI app。

TestClient 不能「先返回响应」？因为 TestClient 的实现方式是「同步等待 ASGI app 返回」。它没有「异步接收响应」的能力——它不是真的在监听 socket，而是在 await app(...)。
