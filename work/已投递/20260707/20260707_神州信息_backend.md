“看你简历写了 SQL 调优，具体是怎么用 Explain 优化的？”

满分回答（务必背诵）：

“在医疗检测系统里，有一张存储面部特征点历史数据的表，数据量很大。当时有个查询接口非常慢。我首先开启了慢查询日志抓到了这条 SQL。然后使用 EXPLAIN 关键字分析它的执行计划。
我发现执行计划里的 type 显示为 ALL（全表扫描），key 字段为 NULL（没有走索引）。原因是因为在 WHERE 条件里，对业务字段进行了函数操作/类型隐式转换，导致索引失效。
我的优化方案是：改写了 SQL 语句，避免了函数计算；同时建立了一个联合索引。改完后重新 EXPLAIN，type 提升到了 ref，走到了我建的索引，查询时间从几秒直接降到了百毫秒级。”

“聊聊 HTTPS 协议是怎么保证接口安全的？”

满分回答（对齐岗位第5条）：

“HTTPS 在传统的 HTTP 层和 TCP 层之间加了一层 SSL/TLS 加密层。它主要通过混合加密来保证数据安全：在连接建立阶段（握手阶段），客户端和服务器通过**非对称加密（RSA 或 ECC）安全地交换对称加密的密钥；在后续的实际数据传输阶段，则使用性能更高的对称加密（AES）**来加密业务数据。同时，通过 CA 证书防止中间人攻击，通过 MAC 摘要算法保证数据完整性，防止接口被篡改。”
