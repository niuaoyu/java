IOC控制反转：类的创建，管理都交给Spring，不需要自己主动new，销毁。靠的是依赖注入DI（Dependency Injection）来实现，底层实现就是用的反射。




AOP主要解决的是那些“横切关注点（Cross-cutting Concerns）”把多个业务方法都会用到的、会横跨很多业务模块、重复出现在很多业务方法中，与核心业务相对独立的公共功能，从业务代码中抽出来，然后在合适的位置自动组合进去，

很多业务都有权限验证、日志、事务这些操作，就是和做成AOP

                用户    订单    支付    商品
                │       │       │       │
权限验证 ───────┼─────┼─────┼─────┼──→
日志记录 ───────┼─────┼─────┼─────┼──→
事务管理───────┼─────┼─────┼─────┼──→
性能监控───────┼─────┼─────┼─────┼──→
                 │           │            │            │
              业务1        业务2       业务3     业务4

AOP不是单纯把“非业务代码”拿出去，而是把那些具有独立职责、横跨多个业务、容易产生大量重复代码的“横切关注点”从核心业务中解耦出来，并通过切入点等机制，在合适的位置统一应用。

三类情况
1. 完全耦合：业务和公共功能（日志，权限）搅在一起
2. 继承解决完全耦合：业务写一个类A，用B extends A，B里写，前置处理+super.业务()+后置处理，可以一定程度解决耦合，但继承关系强
3. 引出静态代理：抽象service接口后，业务A实现这个接口，代理B（管日志，权限等公共事务，调用事务A）也实现这个接口
``` java
interface Service {
    void save();
}

class ServiceImpl implements Service {
	public void save() {
	    System.out.println("真正的业务");
	}
}

class ServiceProxy implements Service {
	private Service target;
	
	public ServiceProxy(Service target) {
	    this.target = target;
	}
	
	public void save() {
	    // 前置
	    System.out.println("日志");
	
	    target.save();
	
	    // 后置
	    System.out.println("记录耗时");
	}
}
```



**AspectJ ≠ JDK动态代理**

静态代理：手动写代理类
JDK动态代理：JDK运行时帮你生成代理对象
CGLIB：运行时生成子类代理
AspectJ：织入（Weaving）

AspectJ的核心思想更接近：**在编译期/加载期等阶段，把切面逻辑织入目标代码。** 原始业务代码 + 切面代码，放一起然后**织入**成最终执行代码




**jdk动态代理和cglib动态代理**

为什么jdk动态代理代理的目标类都必须实现接口呢?
简单说：假设目标类ServiceImpl，如果JDK动态代理，想代理ServiceImpl，理想情况下可能想生成：class $Proxy0 extends ServiceImpl {}

但问题是，JDK动态代理生成的代理类本身需要：extends Proxy，那么就变成：
```
class $Proxy0 extends Proxy, ServiceImpl
```
这跟java单继承不符，但java可以多实现implements，
```
class $Proxy0 extends Proxy implements Service
```
这也是没问题的。

静态代理手写，而且一个方法一个方法都要写
``` java
interface Service {
    void save();
}

class ServiceImpl implements Service {
	public void save() {
	    System.out.println("真正的业务");
	}
}

class ServiceProxy implements Service {
	private Service target;
	
	public ServiceProxy(Service target) {
	    this.target = target;
	}
	
	public void save() {
	    // 前置
	    System.out.println("日志");
	
	    target.save();
	
	    // 后置
	    System.out.println("记录耗时");
	}
}
```
动态代理也是这个思想，可以把“代理逻辑”统一放到 InvocationHandler 里，但不需要手写
``` java
class $Proxy0 extends Proxy implements Service {

    private InvocationHandler handler;

    public void save() {

        handler.invoke(...);
    }
}
```

**静态代理 VS JDK 动态代理**

假设一个接口里有多个方法：
```java
interface Service {

    void save();

    void delete();

    void update();

    void query();
}
```
真实业务类，这个和静态代理完全一样：

```java
class ServiceImpl implements Service {

    @Override
    public void save() {
        System.out.println("执行保存业务");
    }

    @Override
    public void delete() {
        System.out.println("执行删除业务");
    }

    @Override
    public void update() {
        System.out.println("执行修改业务");
    }

    @Override
    public void query() {
        System.out.println("执行查询业务");
    }
}
```
如果是静态代理
```java
class ServiceProxy implements Service {

    private Service target;

    public ServiceProxy(Service target) {
        this.target = target;
    }

    @Override
    public void save() {
        System.out.println("日志");

        target.save();

        System.out.println("记录耗时");
    }

    @Override
    public void delete() {
        System.out.println("日志");

        target.delete();

        System.out.println("记录耗时");
    }

    @Override
    public void update() {
        System.out.println("日志");

        target.update();

        System.out.println("记录耗时");
    }

    @Override
    public void query() {
        System.out.println("日志");

        target.query();

        System.out.println("记录耗时");
    }
}
```
马上就能发现一个问题，4个方法的代理逻辑几乎一模一样。都是：前置->调用真实方法->后置
如果接口有100个方法呢？就得写100遍。JDK动态代理来解决这个问题，JDK动态代理不让自己写：class ServiceProxy implements Service

而是：**JDK运行时帮你生成这个代理类。** 只需要写一个 `InvocationHandler`

```java
import java.lang.reflect.InvocationHandler;
import java.lang.reflect.Method;
import java.lang.reflect.Proxy;

public class Test {

    public static void main(String[] args) {

        // 1. 创建真实业务对象
        Service target = new ServiceImpl();

        // 2. 创建代理对象
        Service proxy = (Service) Proxy.newProxyInstance(
                target.getClass().getClassLoader(),
                target.getClass().getInterfaces(),

                // InvocationHandler
                new InvocationHandler() {

                    @Override
                    public Object invoke(
                            Object proxy,
                            Method method,
                            Object[] args) throws Throwable {

                        // 前置
                        System.out.println("记录日志");

                        // 调用真实业务方法
                        Object result = method.invoke(target, args);

                        // 后置
                        System.out.println("记录耗时");

                        return result;
                    }
                }
        );

        // 3. 调用代理对象
        proxy.save();

        System.out.println("----------------");

        proxy.delete();

        System.out.println("----------------");

        proxy.update();

        System.out.println("----------------");

        proxy.query();
    }
}
```
# 4. 最关键的是这个 `invoke()`

你重点看：

```java
public Object invoke(
        Object proxy,
        Method method,
        Object[] args) throws Throwable {

    System.out.println("记录日志");

    Object result = method.invoke(target, args);

    System.out.println("记录耗时");

    return result;
}
```

这里的：

```java 
method 
```

就是**当前调用的方法**。

所以：

```java
proxy.save();
```

进入：

```text
invoke()
   ↓
method = save()
   ↓
method.invoke(target, args)
   ↓
target.save()
```

如果：

```java
proxy.delete();
```

那么：

```text
invoke()
   ↓
method = delete()
   ↓
method.invoke(target, args)
   ↓
target.delete()
```

如果：

```java
proxy.update();
```

就是：

```text
invoke()
   ↓
method = update()
   ↓
method.invoke(target, args)
   ↓
target.update()
```

所以你会发现：**无论调用接口中的哪个方法，最终都会进入同一个 `invoke()`。** 这就是 JDK 动态代理最核心的地方。

# 5. 把它和你的静态代理对比一下

静态代理，自己写：

```java
class ServiceProxy implements Service {

    public void save() {
        前置();
        target.save();
        后置();
    }

    public void delete() {
        前置();
        target.delete();
        后置();
    }

    public void update() {
        前置();
        target.update();
        后置();
    }

    public void query() {
        前置();
        target.query();
        后置();
    }
}
```

相当于：

```text
save()   ─┐
delete() ─┤
update() ─┼──→ 每个方法自己写代理逻辑
query()  ─┘
```
JDK动态代理，你只写一个：

```java
invoke()
```

```text
save()   ─┐
delete() ─┤
update() ─┼──→ invoke()
query()  ─┘
```

然后：

```java
method.invoke(target, args);
```

再根据 `method` 找到真正的方法。


你可以把JDK生成的代理类想象成这样，**实际生成的代码比这个复杂很多，下面只是帮助你理解。**
，JDK好像帮你生成了：

```java
class $Proxy0 extends Proxy implements Service {

    private InvocationHandler handler;

    @Override
    public void save() {
        handler.invoke(this, saveMethod, null);
    }

    @Override
    public void delete() {
        handler.invoke(this, deleteMethod, null);
    }

    @Override
    public void update() {
        handler.invoke(this, updateMethod, null);
    }

    @Override
    public void query() {
        handler.invoke(this, queryMethod, null);
    }
}
```

于是：

```java
proxy.save();
```

相当于：

```text
$Proxy0.save()
      ↓
handler.invoke()
      ↓
method = save
      ↓
method.invoke(target)
      ↓
ServiceImpl.save()
```

而：

```java
proxy.delete();
```

就是：

```text
$Proxy0.delete()
      ↓
handler.invoke()
      ↓
method = delete
      ↓
method.invoke(target)
      ↓
ServiceImpl.delete()
```

这时候你就能真正理解 `InvocationHandler`，它可以简单理解成：**“代理对象接收到任何方法调用之后，统一交给谁处理？”**,答案就是：`InvocationHandler`

```text
                 Service
                    ↑
                    │
              $Proxy0
                    │
       ┌────────────┼────────────┐
       ↓            ↓            ↓
     save()       delete()      update()
       │            │            │
       └────────────┼────────────┘
                    ↓
           InvocationHandler
                    ↓
              invoke()
                    ↓
          method.invoke(target)
                    ↓
              ServiceImpl
```


**静态代理 = 我自己手写 `ServiceProxy`；JDK动态代理 = 我把“怎么代理”告诉 JDK，JDK帮我生成 `ServiceProxy`，而所有方法的公共代理逻辑集中到 `InvocationHandler.invoke()` 里面。**

这也是为什么它叫**动态代理**：**代理类不是你提前写好的，而是在程序运行时动态生成的。**

引出一个问题，如果一个对象没有接口，怎么代理？这样jdk就不能干了，只能用cglib代理，底层逻辑是继承。

CGLIB解决的就是：目标类没有接口怎么办？例如我们把接口去掉：

```java
public class ServiceImpl {

    public void save() {
        System.out.println("执行保存业务");
    }

    public void delete() {
        System.out.println("执行删除业务");
    }

    public void update() {
        System.out.println("执行修改业务");
    }

    public void query() {
        System.out.println("执行查询业务");
    }
}
```

注意：ServiceImpl没有 implements Service，这时候 JDK 动态代理没法直接代理它。CGLIB采用的是：**生成目标类的子类。** 也就是类似

```java
class ServiceProxy extends ServiceImpl {

    @Override
    public void save() {

        System.out.println("记录日志");

        super.save();

        System.out.println("记录耗时");
    }
}
```

这就是CGLIB的基本思想，CGLIB实际代码

```java
import net.sf.cglib.proxy.Enhancer;
import net.sf.cglib.proxy.MethodInterceptor;
import net.sf.cglib.proxy.MethodProxy;

import java.lang.reflect.Method;

public class CglibProxyTest {

    public static void main(String[] args) {

        // 创建Enhancer
        Enhancer enhancer = new Enhancer();

        // 设置父类
        enhancer.setSuperclass(ServiceImpl.class);

        // 设置方法拦截器
        enhancer.setCallback(new MethodInterceptor() {

            @Override
            public Object intercept(
                    Object obj,
                    Method method,
                    Object[] args,
                    MethodProxy methodProxy) throws Throwable {

                // 前置
                System.out.println("记录日志");

                // 调用父类，也就是真正业务
                Object result = methodProxy.invokeSuper(obj, args);

                // 后置
                System.out.println("记录耗时");

                return result;
            }
        });

        // 创建代理对象
        ServiceImpl proxy =
                (ServiceImpl) enhancer.create();

        proxy.save();
        proxy.delete();
        proxy.update();
        proxy.query();
    }
}
```

CGLIB到底干了什么？你可以把：

```java
enhancer.setSuperclass(ServiceImpl.class);
```

理解成：**帮我生成一个 ServiceImpl 的子类。**，大概类似：

```java
class ServiceImpl$$CGLIBProxy extends ServiceImpl {

    @Override
    public void save() {

        interceptor.intercept(...);

    }

    @Override
    public void delete() {

        interceptor.intercept(...);

    }

    @Override
    public void update() {

        interceptor.intercept(...);

    }

    @Override
    public void query() {

        interceptor.intercept(...);

    }
}
```

然后：

```text
proxy.save()
     ↓
CGLIB子类.save()
     ↓
MethodInterceptor.intercept()
     ↓
methodProxy.invokeSuper()
     ↓
ServiceImpl.save()
```


三种代理放一起，现在就非常清楚了。

 ① 静态代理：**你自己写代理类。**

```text
              Service
              ↑     ↑
              │     │
              │     │
       ServiceImpl  ServiceProxy
                       │
                       ↓
                  target对象
```

 ② JDK动态代理：**JDK运行时生成代理类。**$Proxy0 extends Proxy implements Service  **必须有接口。**

```text
              Service
              ↑     ↑
              │     │
       ServiceImpl  $Proxy0
                       │
                       ↓
              InvocationHandler
                       │
                       ↓
                  target对象
```

③ CGLIB：**CGLIB运行时生成目标类的子类。** 所以：**不要求目标类实现接口。**

```text
          ServiceImpl
              ↑
              │ extends
              │
      ServiceImpl$$Proxy
              │
              ↓
       MethodInterceptor
              │
              ↓
       ServiceImpl业务
```

总结：
```text
                         代理
                          │
             ┌────────────┼────────────┐
             ↓            ↓            ↓
          静态代理      JDK动态代理    CGLIB
             │            │            │
          手写代理类    实现接口       继承目标类
                          │            │
                    InvocationHandler  MethodInterceptor
                          │            │
                          └──────┬─────┘
                                 ↓
                            额外功能
                       日志 / 事务 / 权限
                                 ↓
                            真正业务
```


JDK动态代理本质上就是：JDK在运行时帮我们生成一个“实现目标接口的代理类”，这个代理类继承 `Proxy`，把方法调用统一交给 `InvocationHandler`，然后由 `InvocationHandler` 决定调用目标对象前后要做什么。
