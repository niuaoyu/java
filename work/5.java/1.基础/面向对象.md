# 内存空间

1. JVM分三个空间，所有的.class文件在JVM类加载器作用下加载到方法（内存）区，所有执行的时候，是在JVM栈内存区，优先压main，用到哪个方法压哪个方法入栈。new的对象都存在堆内存里。
2. main函数里调用divide函数int retValue = divide(result, num);，传递参数，这些局部变量参数在新的栈空间需要重新开辟空间
3. 递归很耗栈空间，尽量不用（存在必须使用的情况，后续深入再说），核心写法：终止条件+调用自己。


### 1. 方法区存的是不是所有 Java 代码？

**对，但更准确地说：存的是所有 `.class` 文件的“二进制字节码”和“元数据信息”。**

- 当你用 `java Test` 启动程序时，JVM 会把 **所有需要用到的 `.class` 文件**（Test.class、String.class、System.class 等）加载进方法区。
- 这里存放的是 **“静态的代码蓝图”**（比如方法的指令集、成员变量的签名、常量池等），它只读不执行。
### 2. 局部变量在方法区有空间，执行时栈也有空间，冲突吗？

**完全不冲突，因为它们负责的“生命周期”不同。**

- **方法区里的空间（蓝图）**：描述 `int i = 10;` 这行指令，告诉 JVM“将来如果执行到这里，需要在栈上分配 4 个字节”。它永远只存一份。
- **栈里的空间（运行时实物）**：真正执行到这行时，JVM 才在栈帧里给 `i` 划出 4 字节空间，存具体的值 `10`。
### 核心区别图（对比着看）

| 内存区域 | 存什么 | 何时分配 | 谁负责管理 | 典型例子 |
|---------|--------|---------|----------|---------|
| **方法区** | `.class` 字节码、方法指令、静态变量 | 类加载时（只一次） | JVM 类加载器 | `public static void m0(){ int i = 10; }` 这行指令 |
| **栈内存** | 正在执行的方法的局部变量、操作数栈 | 方法调用时（每次调用都分配） | JVM 栈帧 | 执行 `m0()` 时，栈帧里的 `i = 10` 这个实物 |

### 你图中流程的“内存双视角”

拿你的图举例：

```java
public static void m0() {
    int i = 10;  // 这行代码
}
```

- **方法区视角**：这行代码的字节码被加载，JVM 看到“局部变量 i，类型 int，索引 1”。
- **执行时（栈）视角**：当 `m0()` 被压栈，JVM 就在该栈帧的局部变量表中**创建**一个格子，填上 `10`。`m0()` 弹栈，这个格子和 `10` 一起消失。

**方法区的指令永远不删除，而栈里的变量随着方法弹栈而销毁。**

> **方法区存的是“怎么做”的说明书（字节码指令）；栈内存存的是“正在做”时产生的临时数据（局部变量）。**  
> 两者一个是“静态图纸”，一个是“动态车间”，没有冲突，只有配合。



# 重载

功能类似，可以用重载，比如，整数加减，浮点数加减......就可以用。

要求，只能在同一个类里，函数名一样，但函数参数列表数量不同，或参数顺序不同，参数类型不同。

构造函数和重载的区别和联系？
## 一、一句话区分

> **构造方法** = 用来**创建对象**的“特殊方法”  
> **重载** = 同一个类里**方法名相同但参数不同**的“技术手段”  
> **联系**：构造方法**可以重载**（这是重载的一个应用场景）

## 二、什么是构造方法？

### 特征
```java
public class Customer {
    // 构造方法：方法名 = 类名，没有返回值
    public Customer() {
        System.out.println("对象创建了");
    }
}
```

| 特征 | 说明 |
|------|------|
| 方法名 | 必须和类名完全一致 |
| 返回值 | 没有（连void都不能写） |
| 调用方式 | `new` 对象时自动调用 |
| 作用 | 初始化对象（给属性赋初值） |

### 使用
```java
Customer c = new Customer();  // new 的时候自动调用构造方法
```
## 三、什么是重载？

### 特征
```java
public class Calculator {
    // 方法名相同，参数不同 → 重载
    public int sum(int a, int b) {
        return a + b;
    }
    
    public int sum(int a, int b, int c) {  // 参数个数不同
        return a + b + c;
    }
    
    public double sum(double a, double b) { // 参数类型不同
        return a + b;
    }
}
```

| 特征 | 说明 |
|------|------|
| 方法名 | 必须相同 |
| 参数列表 | 必须不同（个数/类型/顺序） |
| 返回值 | 无关（只看参数） |
| 作用 | 用同一个名字做类似的事情 |

## 四、构造方法的重载（联系）

```java
public class Customer {
    private int id;
    private String name;
    
    // 无参构造
    public Customer() {
        this.id = 0;
        this.name = "未知";
    }
    
    // 有参构造（重载）
    public Customer(int id) {
        this.id = id;
        this.name = "未知";
    }
    
    // 另一个有参构造（重载）
    public Customer(int id, String name) {
        this.id = id;
        this.name = name;
    }
}

// 使用
Customer c1 = new Customer();              // 调用无参构造
Customer c2 = new Customer(100);           // 调用单参构造
Customer c3 = new Customer(100, "张三");   // 调用双参构造
```

**这就是重载在构造方法上的应用：同一个类名，不同的参数，创建对象时灵活选择。**
## 五、对比总结表

| 对比项 | 构造方法 | 重载 |
|--------|---------|------|
| **是什么** | 创建对象的特殊方法 | 同名不同参的技术 |
| **方法名** | 必须 = 类名 | 任意（只要相同即可） |
| **返回值** | 没有（不能写void） | 可以有，但不影响判断 |
| **调用方式** | `new` 时自动调用 | 手动调用 |
| **能否重载** | ✅ 能 | 本身就是重载 |
| **作用** | 初始化对象 | 提供多种调用方式 |

## 六、最容易混的点

### ❹ 构造方法不是“没有返回值”，而是“连void都不能写”

```java
public class Demo {
    // ❌ 这不是构造方法（有void），这是普通方法
    public void Demo() {
        System.out.println("这是普通方法");
    }
    
    // ✅ 这才是构造方法
    public Demo() {
        System.out.println("这是构造方法");
    }
}
```

### ❺ 普通方法也能重载，不限于构造方法

```java
public class Demo {
    // 普通方法重载
    public void print(String s) { }
    public void print(int i) { }
    public void print(String s, int i) { }
}
```
## 七、关系图

```
┌─────────────────────────────────────────┐
│              重载（技术）                │
│   同一个类中，方法名相同，参数不同        │
│                                         │
│    ┌─────────────────────────────────┐  │
│    │     普通方法的重载              │  │
│    │  sum(int a, int b)             │  │
│    │  sum(int a, int b, int c)      │  │
│    └─────────────────────────────────┘  │
│                                         │
│    ┌─────────────────────────────────┐  │
│    │     构造方法的重载              │  │
│    │  Customer()                    │  │
│    │  Customer(int id)              │  │
│    │  Customer(int id, String name) │  │
│    └─────────────────────────────────┘  │
│                                         │
│    构造方法是“特殊方法”，但重载规则一样   │
└─────────────────────────────────────────┘
```

> **构造方法 = 创建对象时自动调用的初始化方法（名=类名，无返回值）**  
> **重载 = 同一个方法名，不同参数列表（管你构造还是普通方法）**  
> **联系 = 构造方法可以重载，让你用不同的方式创建对象**

# 空指针异常

**局部变量不赋值 = 没给地址纸条（编译拦死）**  比如，String  s ; System.out.println(s);
**引用赋 null 后访问 = 纸条上写着“null”（运行才崩）**  比如，String  s = null; System.out.println(s);
**空指针异常的根本原因：用 null 去点 `.` 访问对象的属性/方法**


# static

为什么用引用去访问static不出现空指针异常？这个引用是指具体的实例，但static的方法是类的？

**因为 `static` 方法属于类，不属于对象。**  
用引用去调用时，JVM 在编译阶段就把"引用"替换成了"类名"，**根本不会去管引用指向谁**，所以即使是 `null` 也不报错。
## 一、你的理解完全正确

> "这个引用是指具体的实例，但 static 的方法是类的"

**对！这就是核心原因。**

## 二、编译器的"暗箱操作"

### 你写的代码
```java
Test t = null;
t.doSome();   // 你用引用去调用
```

### 编译器实际执行的代码（等价于）
```java
Test t = null;
Test.doSome();   // 编译器自动替换成"类名."
```

> **关键**：编译器看到 `static` 方法，直接**把前面的对象/引用忽略掉**，换成类名。所以 `t` 是不是 `null`，编译器根本不关心。
## 三、源码验证：反编译看看

```java
// 源文件
public class Test {
    public static void main(String[] args) {
        Test t = null;
        t.doSome();
    }
    
    public static void doSome() {
        System.out.println("do Some!");
    }
}
```

### 反编译后（javap -c）
```
public static void main(java.lang.String[]);
  Code:
   0: aconst_null        // 把null压入栈
   1: astore_1           // 赋给变量 t
   2: invokestatic  #2   // 直接调用 Test.doSome()，跟 t 没关系！
```

**注意**：字节码指令是 `invokestatic`（静态方法调用），不是 `invokevirtual`（实例方法调用）。  
说明 JVM 从头到尾就没想通过 `t` 去找对象。
## 四、对比：实例方法 vs 静态方法

```java
public class Test {
    public static void main(String[] args) {
        Test t = null;
        
        t.doSome();   // ✅ 静态方法 → 不报错
        t.doOther();  // ❌ 实例方法 → NullPointerException
    }
    
    public static void doSome() {
        System.out.println("静态方法");
    }
    
    public void doOther() {
        System.out.println("实例方法");
    }
}
```

| | 静态方法 `doSome()` | 实例方法 `doOther()` |
|--|---------------------|----------------------|
| 编译后调用方式 | `invokestatic` | `invokevirtual` |
| 是否需要对象 | ❌ 不需要 | ✅ 必须要有对象 |
| `null` 调用 | ✅ 正常运行 | ❌ 空指针异常 |
| 建议调用方式 | `类名.方法名()` | `对象.方法名()` |

## 五、为什么 Java 要这么设计？

**静态方法 = 属于类的工具方法**  
它的执行不依赖任何对象的状态（不访问实例变量）

```java
public class MathUtil {
    public static int max(int a, int b) {
        return a > b ? a : b;
    }
}

// 调用
MathUtil.max(10, 20);  // 合理：不需要创建 MathUtil 对象
```

如果非要通过对象调用，Java 允许，但**实际上还是走类调用**，这就造成了"用 null 也不报错"的迷惑行为。

## 六、最容易踩的坑

```java
public class Test {
    private static int count = 0;
    
    public static void main(String[] args) {
        Test t = null;
        t.doSome();  // 能跑！
        
        // 你以为 t 是对象？不，编译器只当它是"类名的别名"
    }
    
    public static void doSome() {
        count++;
        System.out.println(count);
    }
}
```

运行结果：
```
1
```
完全没有问题！`t` 虽然是 `null`，但编译器早就把它替换成 `Test.doSome()` 了。

> **静态方法 = 类的方法**  
> **用"引用"调用静态方法，编译器偷偷把"引用"换成"类名"**  
> **所以引用的值（null 还是对象）完全不影响执行**  
> **建议：永远用 `类名.方法名()` 调用静态方法，避免迷惑**

你截图里的结论非常准确，而且你抓住了本质——**static 和对象无关**。  
这里只是因为 Java 允许用"对象引用"来调用静态方法，但内部还是当成"类调用"处理，所以 null 不报错。
