
正常 Java 是“**编译时就写死**”，反射则允许“**运行时再决定**”


**Java 反射，就是程序运行起来以后，再去查看某个类有什么东西，并且动态地创建对象、调用方法、访问字段。**

反射的本质是把原本编译时确定的一些事情，推迟到了运行时决定。不用反射的时候，必须在编译之前new，然后jvm检查代码是否正确，有了反射，所有的对象的创建都推迟到运行的时候才创建，在编译的时候，所有的类的信息都被加载到方法区里，然后想要用哪个，直接Class.forName("com.xxx.User");获取类
然后Object ob = Class.forName("com.xxx.User").getDeclaredConstructor().newInstance();获取实例

自己理解的：反射反的可以理解为，把获取对象的过程反过来
正常创建对象：User.java --new--拿到对象
反射创建对象：User.java --javac -- User.class -- Class.forName -- 拿到对象
一个是new才能拿到，一个是运行时就可以直接拿到

Spring常用反射，因为Spring目标是少写new，对象组装，依赖查找，代理等基础代码，Spring来找到对象，创建对象，然后塞到业务里，这就需要反射

核心思想就是我不创建对象我哪知道哪里需要对象？反射就是如此，只要在业务里写好注解，当jvm把所有的对象导入到方法区获得对象的class后，就能知道哪里有注解，需要就需要创建对象，就可以直接导进去。
