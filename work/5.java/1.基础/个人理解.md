### 泛型
定义一个类，但不指定具体要的什么数据类型，直接`<T>`
在使用的时候确定传什么类型

特点：优点是集合存储的类型统一，缺点就是集合不够灵活，单大部分需要集合还是类型统一

要理解：可以减少大量的向下转型，因为集合调用的迭代器返回的对象是object，想要专门使用子类方法，必须向下转型，使用泛型后，返回的对象就是在定义的时候的对象，比如
`List<Animal> it = new ArrayList<Animal>();Iterator<Animal> iter = it.iterator()`，
这时候使用的对象就是animal，调用animal的方法不需要向下转型，但如果调用子类方法依旧需要


### 序列化和反序列化

**序列化 = 把对象“拍扁”成字节流，用于存储或传输；反序列化 = 把字节流“复原”成对象，便于使用。**  
它的本质就是**对象状态数据的跨时空转移**——跨越时间（持久化）和空间（网络传输）

网络传输是二进制，java对象没办法网络传输，通过序列化转为二进制，反序列化转为对象，可以在不同环境下运行java对象


### 多线程

线程之间堆空间，方法区共享，但栈内存不共享


**普通线程（用户线程）：会阻止 JVM 退出，JVM 必须等它跑完**  
**守护线程：不会阻止 JVM 退出，JVM 不管它有没有跑完，说杀就杀**
除此之外，并无差别，之所以用守护线程，因为有些线程的工作是辅助性的，存在的意义只是为主程序打杂，主程序都不在了，它自己存在也没意义了。比如，垃圾回收GC，日志异步，这些主程序结束存在也没意义。但有些比如，文件下载，数据库写入，订单相关，必须是普通进程，不能被中断。
守护线程被强制杀死时，**不会执行 finally 代码块，也不会做任何资源释放的收尾工作**，是直接"截断"的。所以：⚠️ 凡是涉及到**文件写入、数据库事务、网络传输**这类需要"有始有终"的操作，**绝对不要**用守护线程去做，否则数据可能损坏或丢失。



start() vs run()

start()**真正创建一个新的线程**，让 CPU 去调度它，新线程和当前线程（比如 main）**并发执行**，谁先跑完不确定。

##run()**只是普通的方法调用**，跟你调用任何一个普通方法没有任何区别。它不会创建新线程，而是在**当前线程**里老老实实、同步地把 run() 里的代码执行完，执行完了才能往下走。

## 代码对比一下就懂了

```java
public class StartVsRun {
    public static void main(String[] args) {
        Thread t = new Thread(() -> {
            System.out.println("子线程: " + Thread.currentThread().getName());
        });
        
        System.out.println("调用前: " + Thread.currentThread().getName());
        
        t.start();   // 或者换成 t.run() 对比着跑一下
        
        System.out.println("调用后: " + Thread.currentThread().getName());
    }
}
```

**用 `t.start()`：**

```
调用前: main
子线程: Thread-0     ← 新开了一个线程在跑，名字不是main
调用后: main
```

（顺序甚至可能是"调用后"先打印出来，因为两个线程谁先谁后不确定）

**如果换成 `t.run()`：**

```
调用前: main
子线程: main          ← 注意！还是 main 线程，没有新线程
调用后: main
```

三行严格按顺序打印，因为本质上就是**在 main 线程里顺序调用了一个方法**，跟写 `t.run();` 和写别的方法调用（比如 `doSomething();`）完全一样。

## 一句话总结

||start()|run()|
|---|---|---|
|是否创建新线程|✅ 是|❌ 否|
|执行方式|并发（异步）|同步（跟普通方法调用一样）|
|Thread.currentThread() 打印的名字|新线程名（如 Thread-0）|调用者所在线程的名字（如 main）|

**记忆技巧**：`start()` 才是"启动线程"这个动作本身；`run()` 只是"线程要执行的任务内容"，你不通过 `start()` 去触发它，它就只是一个躺在那里的普通方法，谁调用它就在谁的线程里跑。
