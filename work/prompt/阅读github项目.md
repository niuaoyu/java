prompt：
推荐一下阅读顺序？



**正确的顺序是从外到内，从粗到细：**

| 层次 | 你要搞懂什么 | 具体动作 | 产出物 |
|------|-------------|---------|--------|
| **第1层：项目定位** | 这个项目是干什么的？解决什么问题？为什么有这个项目？ | 读 README、看项目介绍、了解背景 | 一句话概括项目使命 |
| **第2层：架构全景** | 整体怎么设计的？有哪些核心模块？它们怎么交互？ | 看架构图（如果有）、目录结构、模块划分 | 画出模块关系图（手画也行） |
| **第3层：核心流程** | 一条完整请求/任务从进到出是怎么走的？ | 跟一个最简单的端到端流程（如用户登录→返回结果） | 画出时序图（谁先调谁） |
| **第4层：关键实现** | 最核心的那个逻辑是怎么写的？用了什么技巧/模式？ | 深入阅读核心模块的核心函数（只看关键部分，不看细枝末节） | 摘录关键代码片段 + 注释 |
| **第5层：吸收内化** | 哪些设计思想/代码技巧能用到我自己的项目里？ | 对比自己之前的写法，找出差异和改进点 | 输出一篇“吸收笔记” |

> **关键原则**：**不要逐行读代码，要带着问题去“寻找答案”**。比如“如果让我写这个功能，我会怎么写？项目里是怎么写的？好在哪？”

## 二、可以直接用的 Prompt 模板

你可以把下面这个 Prompt 直接发给 AI（ChatGPT/Claude/DeepSeek 等），把 `[项目名称]` 和 `[GitHub链接]` 替换掉。

```
我需要深入理解这个 GitHub 项目，目标是吃透它的核心设计，并把精华吸收到自己的编码实践中。我是该项目领域的小白，请按以下 5 个层次帮我拆解，每一层输出具体内容：

**【第1层：项目定位与背景】**
- 这个项目解决的是什么问题？为什么需要它？
- 它的核心价值是什么？（用一句话说清楚）
- 它有哪些竞品？它和竞品最大的不同是什么？

**【第2层：架构设计与模块划分】**
- 整体架构是什么样的？有哪些核心模块？
- 各模块之间的依赖关系和交互方式是什么？
- 用 Mermaid 或文字画出模块关系图。
- 它的目录结构是如何组织代码的？这种组织方式有什么好处？

**【第3层：核心流程（端到端）】**
- 选取最典型的一个使用场景（如一次查询、一个请求），完整追踪它的执行路径。
- 从用户输入到最终返回结果，经历了哪些关键步骤？
- 每一步由哪个模块/类/函数负责？用文字或时序图描述。

**【第4层：关键实现与设计亮点】**
- 最核心的那个算法/逻辑是如何实现的？
- 它用了哪些设计模式？解决了什么特定问题？
- 代码中有哪些“精巧”的设计（比如缓存策略、并发模型、扩展机制）？
- 有哪些地方让我觉得“如果是我写，我肯定会写成XXX，但它用了YYY方式，好在哪”？

**【第5层：吸收与迁移（最重要）】**
- 这个项目给我最大的 3 个启发是什么？
- 它的哪些设计思想/代码技巧可以迁移到我的日常开发中？
- 如果我要写一个类似的小项目，我应该模仿它的哪些方面？避开它的哪些缺陷？
- 请给我一个“学习行动计划”——按什么顺序读哪些文件，最能高效吸收精华。

项目名称：[填写项目名称]
GitHub 链接：[填写链接]
我的技术背景：[比如“有X年Java后端经验，熟悉Spring Boot，但不熟悉该领域”]
我当前想重点学习的方向：[比如“它的扩展机制/性能优化/领域建模”]
```

3. **做“反推练习”**：每看懂一个模块，就合上代码，自己用文字描述一遍“如果让我设计这个模块，我会怎么做”，再和项目实际做法对比。差距就是你的收获。

4. **分阶段问**：不要一次性让 AI 输出所有层次（上下文太长容易遗漏）。可以分 3 轮：
   - 第1轮：问第1~2层（定位+架构）
   - 第2轮：问第3~4层（流程+实现）
   - 第3轮：问第5层（吸收迁移）
