时间分配（假设你有6-8周）

- **Week 1-3**：做1个能讲的项目（60%精力）
- **Week 2-4**：刷算法题（30%精力）
- **Week 4-6**：投简历 + 准备面试（10%精力，逐渐增加）
    

Week 1-3：做一个能讲的项目

为什么不做"学完再做"？因为**面试官不关心你学了什么，只关心你做了什么**。

### 项目选择标准

1. **必须能跑起来**（演示时不能崩）
2. **必须有技术亮点**（能回答"为什么这么设计"）
3. **必须在3周内能完成**（不能太复杂）
    

### 推荐项目：智能文档问答Agent

**为什么选这个？**

- 技术栈完整：LLM调用 + 向量数据库 + RAG
- 容易演示：上传PDF → 问问题 → 得到答案
- 面试常问：检索策略、向量化、提示工程
    

**3周开发计划**：

#### Week 1：MVP（最小可用版本）

**Day 1-2**：环境搭建 + 基础框架

```python
# 目标：能调用LLM API，能读取PDF
项目结构：
simple-doc-qa/
├── main.py          # 入口
├── llm_client.py    # LLM调用封装
├── pdf_parser.py    # PDF解析
└── requirements.txt
```

**验收标准**：

- 能用OpenAI/Claude API回答问题
    
- 能读取PDF并提取文本
    

**Day 3-5**：基础问答流程

```python
# 目标：用户上传PDF → 提问 → 返回答案
核心功能：
1. 读取PDF
2. 分段（按段落或固定长度切分）
3. 把所有段落拼到prompt里
4. 调用LLM生成答案
```

**验收标准**：

- 能上传一个PDF
    
- 能问一个问题
    
- 能得到基于文档的答案
    

**Day 6-7**：加一个简单的Web界面

- 用Streamlit（最快）或Gradio
    
- 验收标准：朋友能打开网页使用
    

#### Week 2：加技术亮点

**Day 8-10**：加向量检索

```python
# 为什么加这个？面试会问"文档太长怎么办"
技术选型：
- 向量数据库：Chroma（本地，简单）
- Embedding：OpenAI text-embedding-3-small

改造：
1. 上传PDF时，分段 + 向量化 + 存入Chroma
2. 提问时，问题向量化 → 检索top-k相关段落 → 拼入prompt
```

**验收标准**：

- 能处理超过10页的PDF
    
- 检索时间<2秒
    

**Day 11-14**：优化检索策略

- 加重排序（可选，如果有时间）
    
- 加滑动窗口（段落有overlap）
    
- 记录检索日志（哪些段落被检索了）
    

**验收标准**：

- 答案质量明显提升
    
- 能在面试时讲清楚"为什么这么设计"
    

#### Week 3：完善 + 准备面试材料

**Day 15-17**：代码优化

- 加异常处理
- 加日志
- 写README（项目介绍 + 如何运行）
- 补几个单元测试
    

**Day 18-21**：准备面试话术  
写一份`INTERVIEW_GUIDE.md`，包含：

1. **项目背景**：为什么做这个？解决什么问题？
2. **技术架构**：画一个流程图（mermaid）
3. **技术选型**：为什么用Chroma不用Pinecone？为什么用这个分段策略？
4. **遇到的坑**：比如检索结果不准，怎么优化的？
5. **可改进的点**：如果有更多时间，你会怎么优化？
    


## 💻 Week 2-4：刷算法题

### 为什么不是"刷完再做项目"？

因为：

1. 项目更重要（面试80%时间在问项目）
    
2. 算法可以并行刷（每天1-2小时）
    
3. 刷太多也记不住，刷50道核心题就够
    

### 刷题策略

**目标**：笔试不挂（不是拿满分）

**题目来源**：LeetCode Hot 100 → 选50道

**分类刷**（每天5题，10天刷完）：

1. **数组/字符串**（10题）：双指针、滑动窗口
    
2. **链表**（5题）：反转、合并
    
3. **树**（10题）：遍历、递归
    
4. **动态规划**（10题）：背包、最长子序列
    
5. **其他**（15题）：栈、队列、哈希表、二分
    

**刷题流程**：

1. 看题 → 想5分钟 → 看答案 → 手写一遍 → 提交
    
2. 第二天复习昨天的题
    
3. 一周后再复习一遍
    

**验收标准**：

- 50道题都能在15分钟内写出来
    
- 能讲清楚思路

## 📝 Week 4-6：投简历 + 面试

### 简历怎么写？

**项目描述模板**：

```
【项目名称】智能文档问答Agent

【项目描述】
基于LLM和向量检索的文档问答系统，支持PDF上传和智能检索。

【技术栈】
Python, FastAPI, OpenAI API, Chroma, Streamlit

【核心功能】
1. PDF解析和分段处理，支持10MB+文档
2. 基于向量检索的相关段落提取，检索准确率85%+
3. 优化检索策略（滑动窗口+重排序），答案质量提升40%

【技术亮点】
1. 实现了分段策略优化，解决了长文档上下文丢失问题
2. 使用Chroma向量数据库，检索速度<2s
3. 设计了检索评估机制，持续优化检索效果
```

**注意**：

- 数字要具体（不要说"提升了效果"，要说"提升了40%"）
    
- 突出技术难点（不要只说"实现了XX"，要说"解决了XX问题"）
    

### 投简历策略

**第一批**（Week 4）：投20家

- 大厂（腾讯、字节、阿里）：练手
    
- 中厂（小红书、B站、快手）：保底
    
- 创业公司：容易拿offer
    

**目标**：

- 拿到5个笔试机会
    
- 拿到2-3个面试
    

### 面试准备

**项目怎么讲**（5分钟版本）：

1. **背景**（30s）：做这个项目是因为...
    
2. **方案**（2min）：技术架构 → 画图 → 核心模块
    
3. **难点**（1.5min）：遇到什么问题？怎么解决的？
    
4. **成果**（1min）：效果如何？数据支撑？
    

**常见问题准备**：

1. "为什么用这个技术栈？"
    
2. "如果文档很大，怎么优化？"
    
3. "检索不准怎么办？"
    
4. "如果让你重新做，会怎么改进？"
