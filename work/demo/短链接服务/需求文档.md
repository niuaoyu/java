接口名称：短链接转移
Method + 路径：GET  ，/links/{url}
请求参数（body/path/query，字段名+类型+是否必填）：{short_url":"https://shorturl.com" }
成功响应（状态码 + body示例）：{"code":"302","Location":"https://longurl.com" }
失败响应（状态码 + body示例，覆盖所有可能的错误情况）：{"code":"400","body":{"message":"该链接不存在或已失效"}}


数据库表
长短链接对应表（longtoshort）
字段：hashid(int(8),、primary key、唯一约束 ) 、longurl（varchar（100））、shorturl（varchar（10））
hashid根据longurl计算出来的hashid，然后shorturl根据hashid+某种固定规则，得到的shorturl这样因为hashid唯一，这样得到的shorturl也唯一，如果多次插入一个longurl，更新shorturl，给定一些规则，比如 hashid+规则1（规则2.....，一直往上加最简单的加数字，hashid=11111111，shorturl=1111111101，1111111102，一直到1111111199）

1.同时提交两次，返回的是新的短链，旧的链接失效，覆盖表上longurl对应的shorturl
2.短链不存在，不管是api访问还是app还是web访问都可以返回json文件，如果是web或app返回的json由前端拿到json的message信息跳转到信息页面（渲染message信息），如果是api直接返回json的message

# 需求

1.作为用户，我想要提交一个长链接，以便于可以分享给别人短链接
验收标准：1.给一个合法的链接http:// 或 https://  当我提交时，应该返回短链。2.给一个非法的链接或空链接，当我提交时，应该返回错误提示（url无效）

2.作为用户，我想要通过一个短链，拿到真实的地址，以便于看到短链后的真实内容
验收标准：1.给定一个短链接，当点击时，应该跳转到真实内容。

3.作为用户，我想要在短链不存在时收到明确提示，以便我知道这个链接是坏的
验收标准：1.给定一个不存在的短链接，当点击时，应该跳转到"该链接不存在或已失效"。
