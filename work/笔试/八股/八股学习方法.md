
不是背来的，要写代码验证，看源码（ai辅助）记录思考过程。

核心原则是：**「理解 > 背诵」，「代码验证 > 纯看文字」**。

```
┌─────────────────────────────────────────────┐
│  Step 1: 用 3 分钟看完概念（是什么）           │
│  Step 2: 问自己「为什么这样设计？不这样会怎样？」│
│  Step 3: 写 Demo 代码验证（跑起来！）          │
│  Step 4: Debug 进源码（关键方法打断点）         │
│  Step 5: 画图总结（脑图/流程图/时序图）         │
│  Step 6: 用自己的话讲出来（费曼学习法）         │
└─────────────────────────────────────────────┘
❌ 错误方式：看八股文合集 → 背 → 忘 → 再背 → 面试被追问 → 懵
⚠️ 最大的误区：只停留在第1层「背概念」。面试官一追问就露馅。
✅ 正确方式：理解原理 → 写代码验证 → 读源码 → 画图总结 → 讲出来
```
高效的路径是：**理解设计动机 → 代码/工具验证 → 用自己的话复述**。

> **八股不是背出来的，是「跑」出来的。每个知识点都写个 Demo，Debug 进源码看一遍，画一张图，用自己的话讲一遍 —— 这样的一个知识点，顶你背十个。**

学习方法：
1. **以面试题为索引倒推学习**：先看目标岗位的面经，从真题出发去补原理，避免地毯式看书浪费时间。
2. **费曼输出**：每个专题学完，合上资料，对着白纸讲一遍（或写博客/笔记）。讲不顺的地方就是没懂的地方。
3. **建立追问树**：模拟面试官连环追问。例如：Redis 为什么快 → 单线程为什么快 → 6.0 为什么引入多线程 → 多线程用在哪。自己把追问链画出来。
4. **和项目绑定**：把八股嫁接到你的项目上——"我项目里线程池参数是怎么定的""缓存一致性我是怎么处理的"。**八股 + 项目场景 = 面试最强组合**，纯八股谁都会背，能落到场景才有区分度。



## 一、🧠 学习总原则：三层递进法

```
第1层：概念理解（是什么？为什么？）    → 看文档/博客/视频
第2层：代码验证（真的是这样吗？）      → 写 Demo 跑一跑
第3层：源码追踪（底层怎么实现的？）    → Debug 进源码
```

每学一个知识点，问自己三个问题：

1. **为什么要有它？**（解决什么问题）
2. **不用它会怎样？**（反面推导）
3. **它的代价是什么？**（trade-off，这是区分高手的关键）

比如学 HashMap，不是背"数组+链表+红黑树"，而是理解：为什么链表长度到 8 转红黑树？为什么扩容是 2 倍？为什么 1.8 改成尾插法？——这些追问链才是面试真正考的东西。

### 1️⃣ Java 基础（优先级：⭐⭐⭐⭐⭐）

| 知识点 | 最佳学习方式 |
|--------|------------|

| ConcurrentHashMap | ✅ **对比 JDK7（分段锁）和 JDK8（CAS+synchronized）**，Debug 看锁粒度 |

| 反射/动态代理 | ✅ **手写一个简易 AOP**，比背100遍概念都有用 |
| 泛型/类型擦除 | ✅ 写泛型代码，反编译看字节码 |

```java
// 例：验证 HashMap 扩容 —— 这种代码一定要自己跑
```

```java
public class VisibilityDemo {
    // 去掉 volatile 观察线程是否能停下来
    private static volatile boolean flag = true;

    public static void main(String[] args) throws InterruptedException {
        new Thread(() -> {
            while (flag) { /* 空转 */ }
            System.out.println("线程停止");
        }).start();

        Thread.sleep(1000);
        flag = false;
        System.out.println("main 设置 flag = false");
    }
}
```
