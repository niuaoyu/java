
同步 ≠ “CPU 一个时刻不能做别的”，阻塞 ≠ “CPU 在那里干等”。

同步：调用者**需要**主动获取最终结果，比如不断的read，不是说~~线程必须**亲自等到**结果才能往下走~~，因为按照必须等到结果才能往下走的理解话，同步非阻塞就理解不透了，因为当前结果没拿到，线程A不是啥也不干，

异步：调用者**不需要**主动read获取最终结果，系统会完成后告诉调用者

==所以这个同步异步都只是针对当前线程来说的，同步说明当前线程上一条没执行完不能执行下一条，异步说明上一条没执行完，可以执行下一条==

同步异步只关注最终结果怎么交付？同步是说调用方主动发起检查得到结果，异步是提交操作后，系统完成，并通知调用方交付结果。

阻塞的这个干等容易误解，不是cpu干等，而是这个任务被挂起，对于这个任务来说是阻塞，cpu就去做别的事情了

非阻塞：现在没结果，立刻告诉cpu没有，但别挂起当前线程，线程继续执行


阻塞模式下，"谁"在负责发现数据好了？
答案：硬件中断 + 内核，不需要任何"轮询"这个动作。"检查有没有准备好"这件事是操作系统内核帮你做的，是靠硬件中断触发、被动通知内核完成的，不是靠某个线程反复去问（轮询）完成的。 



**同步阻塞（什么都不能干）**：线程A调用服务B，但服务B没准备好，于是线程A被挂起（这就是阻塞），此时线程A失去操作CPU权限，CPU执行别的线程，**操作系统内核负责检查服务B是否准备好**，当服务B准备好后，唤醒线程A，获得CPU资源，继续执行线程A的其他任务

```java
result = read(socket);     // ← 这一行,线程A被内核挂起,零参与,不能执行任何代码
use(result);                // ← 只有拿到result后,这一行才能跑
doOtherTask();               // ← 这一行必须排在use(result)后面执行(因为是同一个线程,代码是顺序执行的)

```
 doOtherTask() 想执行，前提是CPU得先跑完 read(socket) 这一行的调用点,因为被os挂起，已经卡住了，走不到doOtherTask() ，所以同步阻塞里"不能做别的事"，**本质原因不是"同步"**，而是"阻塞"（线程被物理挂起，任何代码都执行不了，包括你想插进去的其他任务）


**同步非阻塞（可以做别的事，依然是"同步"）**：线程A调用服务B，但服务B没准备好，因同步所以要调用方线程A**主动轮询**服务B，因非阻塞所以不挂起，当线程A轮询没结果时，不能执行当前线程的其他任务，卡住了，但此时失去CPU权限，CPU去做别的事情了，定时回来轮询服务B准备好没，准备好了继续走线程A的下面任务
```java
while (true) {
    result = tryRead(socket);   // 非阻塞调用,立即返回(可能是"暂无数据")
    if (result != null) break;  // 一旦有结果,跳出循环
    doOtherTask();               // ← 没有结果时,可以执行这一行
}
use(result);                     // ← 只有跳出循环(即result就绪)后,这一行才能执行
```
这里"同步"体现在哪？ 就体现在最后这一行 use(result)：它无论如何都必须等到 result != null 才会被执行到，这跟同步阻塞是完全一样的约束——结果的消费方，必须是调用方自己，且必须等到结果才能继续。

"非阻塞"体现在哪？ 体现在 tryRead() 这个调用本身：它不会让线程挂起，执行完立刻返回（不管有没有结果），于是线程可以在还没等到结果的这段时间里，插入执行 doOtherTask()。


异步非阻塞：线程A调用服务B，但服务B没准备好，异步说明服务B可以主动返回信号，不需要轮询，因非阻塞所以不挂起，线程A可以在轮询没结果时，执行当前线程的其他任务





异步阻塞：线程A调用服务B，但服务B没准备好，于是线程A被挂起（这就是阻塞，同样线程A不能执行任何任务），因为是异步（），当os检查到服务B准备好，发信号给调用方线程A，线程A接收到信号，被唤醒，获得CPU资源，继续执行线程A的其他任务







异步阻塞 == “异步操作 + 阻塞等待结果”
