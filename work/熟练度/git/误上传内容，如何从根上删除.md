这个图很形象，三个部分。工作区，版本库（stage，main），所有乱七八糟的更改，只要没有`git add .` 到stage区，都没有被追踪，随时可以被覆盖丢掉，也就是到了stage区就可以被.git这个文件夹记录状态，而commit提交到main，就是彻底被保存了当前的信息，这里其实不需要在意远端origin main，就把远端当做本地被追踪的stage，commit的备份而已。

```
本地仓库 (你的电脑)                        远程仓库 (GitHub)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

│ Commit A (已push)    │ ─── git push ──→ │ Commit A (已接收)    │
│ Commit B (已push)    │ ─── git push ──→ │ Commit B (已接收)    │
│ Commit C (未push)    │                  │ (不存在)             │
│ Tag v1.0 (已push)    │ ─── git push ──→ │ Tag v1.0 (已接收)    │
│ Tag v2.0 (未push)    │                  │ (不存在)             │
└─────────────────────┘                  └─────────────────────┘
```
注意：tag和commit不能否用一个push推送，必须分两次push，或者使用特殊参数。git push 默认只推送**分支**的commit,**tag不会自动推送**，必须显式指定，再次注意必须先推commit再push tag，反过来的话，推的tag不是当前最新的版本信息
``` bash
git commit -m ":ssss"
git push origin main  # 只推送commit，不推送tag！

两种方式最安全
git commit -m ":ssss"
git tag v0.1.0-mvp           # 创建commit和tag
git push origin main         # 先推送commit
git push origin v0.1.0-mvp   # 再推送tag

另外一种
git push origin main --tags  # 同时推送分支和所有tag

```



```plain
git checkout -- del/del.txt
```
命令意思是，把`del.txt`文件在**工作区**的修改全部撤销，这里有两种情况：
一种是`del.txt`自修改后还没有被放到暂存区，现在，撤销修改就回到和版本库一模一样的状态；
一种是`del.txt`已经添加到暂存区后，又作了修改，现在，撤销修改就回到添加到暂存区后的状态。

总之，就是让这个文件回到最近一次`git commit`或`git add`时的状态。这里最近可以考虑如果先commit后，然后修改很多，再add但没commit，这时候再在工作区修改很多，然后checkout的东西就是暂存区的东西，而不是commit，反正总之暂存区有东西，那checkout就是暂存区的东西，没东西那么就回退到commit的时候

如果是没有`git add .` ，说明暂存区是空的，那么checkout自然修改到和版本库（最新commit）一样的状态了！

场景
1. 如果改错了代码，想丢弃当前修改的所有东西，那么直接git checkout -- '某个文件' 就行了，如果有的地方想保存那先git add '文件'，再checkout，这样丢的就是不想要的了！
2. 但，如果已经add 某个文件了，但是又不想要了，单独撤销某个文件，有以下几个方法
	1. git reset HEAD del/del.md 等价于 git restore --staged del/del.md，这时候del.md这个被stage的文件通过看git status 就有绿色（被追踪）变成红色（没被追踪），最好用restore直观一些，reset有其他功能，容易冲突，就像前面的checkout一样
	2. 撤销所有暂存的文件，`git reset HEAD` 把暂存区重置为HEAD指向的commit，但**保留工作区的修改**，类似`git restore --staged .` 这种回退的功能应该都是类似的，暂存区变成commit的内容，工作区不变！
	3. git reset --hard HEAD    **暂存区清空，工作区的所有未提交修改全部丢失**（无法恢复），也就是直接回退到之前commit的版本，当前任何工作区和暂存区的东西全部丢失，执行这个命令之前最好先新建checkout一个分支，`git checkout -b temp-backup`，然后再add commit，之后再切回来`git checkout main && git reset HEAD --hard`，后续不对劲再切回分支合并回main！
	4. `git rm --cached <file>`（特殊场景），直接移除文件，不再追踪，比如误把.env add了，那么先移除，然后再添加到.gitignore文件里即可
3. 

撤销所有暂存文件，执行 `git reset HEAD` 后，git reset HEAD 把暂存区重置为HEAD指向的commit，但保留工作区的修改，那如果del.md文件先git add del.md后，del.md又被修改了，如果此时想要git reset 把所有暂存区的东西退掉，这时候有三个版本，一个是之前commit的，一个是暂存区的，一个是工作区最新修改的，这三个用的是哪个？`del/del.md` 的内容变成**哪个版本**？**答案：暂存区被重置为"之前commit的版本"，工作区保持不变（还是你最新修改的内容）。** 也就是说：**之前commit的版本** → 变成暂存区的内容，**暂存区的版本** → 被丢弃（没了），**工作区最新修改的版本** → 保留（不受影响）




如果想要退回到过去的某个commit的节点，但当前自己的分支dev还是三个状态，一个是最新commit的，一个是commit之后修改的代码，暂存区新add的，一个是工作区在add后又最新修改的，这三个的状态要怎么变化？

**`git reset` 的三个参数决定了三个区域如何变化：**

| 参数             | 本地仓库(HEAD) | 暂存区  | 工作区  | 安全等级   |
| -------------- | ---------- | ---- | ---- | ------ |
| `--soft`       | ✅ 回退       | ❌ 不变 | ❌ 不变 | 🟢 最安全 |
| `--mixed` (默认) | ✅ 回退       | ✅ 回退 | ❌ 不变 | 🟡 中等  |
| `--hard`       | ✅ 回退       | ✅ 回退 | ✅ 回退 | 🔴 最危险 |

`git reset --soft <commit-hash>` 回退到某个commit状态，重新开启新的节点
`git reset --mixed <commit-hash>`  其实跟soft没差太多，可能想要stage的内容，这时候就`git checkout -- .` 在下面，有具体的解释
`git reset --hard <commit-hash>`

`git checkout -- .` 是把所有stage的内容返回到工作区，假设工作区在之前add追踪后又修改了一些，那么执行git checkout -- . 后，返回的就是直接覆盖工作区更新的内容，
```
执行前：
HEAD:    v1
暂存区:  v2 (已add)
工作区:  v3 (add后又修改了)

执行 git checkout -- . 后：
HEAD:    v1
暂存区:  v2 (不变！)
工作区:  v2 (被强制覆盖，v3 丢失！)

结果：工作区回到 v2（暂存区的版本），v3 永久丢失
```

`git restore --staged .` **只操作暂存区，完全不碰工作区** 
```
执行前：
HEAD:    v1
暂存区:  v2 (已add)
工作区:  v3 (add后又修改了)

执行 git restore --staged . 后：
HEAD:    v1
暂存区:  变成 HEAD 指向的版本（v1 或更早？？为什么会更早？大概率就是HEAD）
工作区:  v3 (不动工作区)

结果：工作区 v3 被完整保留，没有被覆盖
```

| 命令                                           | 操作对象 | 暂存区变化 | 工作区变化     | 工作区新修改(v3) |
| -------------------------------------------- | ---- | ----- | --------- | ---------- |
| `git checkout -- .`<br>`git restore .`       | 工作区  | ❌ 不变  | ✅ **被覆盖** | ❌ **丢失**   |
| `git restore --staged .`<br>`git reset -- .` | 暂存区  | ✅ 重置  | ❌ 不变      | ✅ **保留**   |
