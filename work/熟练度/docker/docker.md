### 镜像image 容器container 仓库repository

**Docker 镜像是一个只读的模板，包含了运行应用所需的一切：代码、运行时、库、环境变量和配置文件。** 类比：**镜像就像是一张光盘或 ISO 文件**。你可以用同一张光盘在不同电脑上安装系统，而光盘本身不会被修改。同样，一个镜像可以创建多个容器，而镜像本身保持不变。

images镜像相当于**类**，容器container相当于**类的实例**（镜像是静态的定义，容器是镜像运行时的实体。容器可以被创建、启动、停止、删除、暂停等）






**docker客户端只负责下令，docker守护进程在后台执行，docker主机提供场地**

现实开发中，**我们常常把 Docker 主机部署在云服务器上**，然后用自己的笔记本电脑（客户端）通过 `ssh` 或远程 API 去连接它。
如果笔记本装了 Docker Desktop，那笔记本既是客户端，也是主机（守护进程也在你笔记本里）
如果你连到阿里云服务器，那**云服务器**是主机，你的笔记本只是客户端。

可以理解
docker主机是提供资源的东西——厂房
docker守护进程是执行操作的——工人
docker客户端只负责发指令——老板


dockerfile：输入代码和环境，打包得到一个镜像，记录好一道菜的来龙去脉，如何洗，如何做
docker-compose.yml：输入镜像，然后启动所有镜像，不负责做菜，只负责摆盘上桌
**Dockerfile 解决“怎么做一个容器”**，**docker-compose.yml 解决“怎么把多个容器串起来一起跑”**

docker compose 多容器管理工具，通过yaml配置文件，一键启动，关闭多个关联容器


端口映射

docker run --name mysql-niu -p 9999:3306 ，这句话-p 9999:3306 就是端口映射
任何访问mysql容器的请求都需要通过9999这个端口才能找到mysql容器
但如果内部容器访问mysql容器，就直接localhost:3306即可

简单理解：端口映射是，宿舍楼:房间号，外卖人员想找房间号，必须找对宿舍楼


容器间通信，四种模式：桥接（再加个自定义桥接），host，none，container


数据卷挂载：

把容器外部（你电脑）的一个文件夹，映射到容器内部的一个文件夹，让两者保持同步
既然是同步，那么二者本质是一个东西，我改你也改
容器里也有目录，但容器一删，数据都没了，有挂载就是解决这个问题
