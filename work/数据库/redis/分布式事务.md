

> **ACID事务解决的是单个数据库内部的数据一致性问题。**
> **分布式事务解决的是多个服务/多个数据库之间的数据一致性问题。**
> **Redis事务（MULTI/EXEC）只是Redis提供的一组命令批量执行机制，并不等价于ACID事务，也不是完整分布式事务。**


ACID事务是什么？ACID通常指关系型数据库事务，比如MySQL。
例如：银行转账，A转账B，要么一起成功要么一起失败，失败回滚。这就是ACID。

ACID四个特性
1. Atomicity 原子性：一个事务中的操作，要么全部成功，要么全部失败。
2. Consistency 一致性：数据必须满足业务规则（转账后，不能凭空多出钱来）。
3. Isolation 隔离性：多个事务同时执行，不能互相影响。例如两个用户同时买最后一个商品，不能都买到了
4. Durability 持久性：提交commit后，数据永久保存，服务器重启数据还在。

分布式事务为什么难？
因为多个机器多个数据库存放：订单数据库，库存Redis，支付数据库。
每个地方都有自己的事务。但是没有一个统一事务。



**分布式事务解决方案**

## 1. 两阶段提交 2PC

流程：

第一阶段：

询问：

```
库存服务：
可以提交吗？

支付服务：
可以提交吗？
```

第二阶段：

统一：

```
commit
```

或者：

```
rollback
```

缺点：

性能差。

容易阻塞。

---

## 2. TCC

Try：

预留资源。

Confirm：

确认。

Cancel：

取消。

例如：

扣库存：

Try：

```
冻结库存10个
```

Confirm：

```
真正扣除
```

Cancel：

```
释放冻结
```

---

## 3. 消息最终一致性

现在互联网最常用。

例如：

支付：

```
订单服务
 |
发送消息
 |
MQ
 |
库存服务
```

失败：

重试。

最终：

达到一致。

# 八、Redis在分布式事务里面干什么？

Redis一般不是承担事务核心。

常见作用：

---

## 1. 分布式锁

例如：

抢订单：

只有一个服务操作。

例如：

订单状态：

```
UNPAY

PAYING

SUCCESS
```

存Redis：

快速查询。

## 3. 幂等控制

防止重复支付。

例如：

支付请求：

```

```

第二次：

发现存在：

直接返回。
