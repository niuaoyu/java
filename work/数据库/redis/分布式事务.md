

> **ACID事务解决的是单个数据库内部的数据一致性问题。**
> 
> **分布式事务解决的是多个服务/多个数据库之间的数据一致性问题。**
> 
> **Redis事务（MULTI/EXEC）只是Redis提供的一组命令批量执行机制，并不等价于ACID事务，也不是完整分布式事务。**

---

# 一、ACID事务是什么？

ACID通常指关系型数据库事务，比如MySQL。

例如：

银行转账：

账户A：

```
余额1000
```

账户B：

```
余额500
```

执行：

```sql
begin;

update account
set money=money-500
where id=A;


update account
set money=money+500
where id=B;


commit;
```

要求：

要么：

```
A -500
B +500
```

一起成功。

要么：

```
A不变
B不变
```

失败回滚。

这就是ACID。

---

# 二、ACID四个特性

## 1. Atomicity 原子性

意思：

> 一个事务中的操作，要么全部成功，要么全部失败。

例如：

转账：

```
扣A
加B
```

不能：

```
A扣了
B没收到
```

否则钱凭空消失。

MySQL：

```
ROLLBACK
```

实现。

---

## 2. Consistency 一致性

意思：

> 数据必须满足业务规则。

例如：

银行：

转账前：

```
总金额=10000
```

转账后：

```
A减少500
B增加500
```

总金额：

```
仍然10000
```

---

## 3. Isolation 隔离性

多个事务同时执行：

不能互相影响。

例如：

两个用户同时买最后一个商品。

事务A：

```
库存=1
```

事务B：

```
库存=1
```

不能都购买成功。

---

## 4. Durability 持久性

提交后：

数据永久保存。

例如：

```
commit成功
```

服务器重启：

数据还在。

---

# 三、Redis事务是什么？

Redis：

```redis
MULTI

SET name mao

INCR age

EXEC
```

Redis保证：

## 1. 命令按顺序执行

例如：

进入队列：

```
SET A
SET B
SET C
```

执行：

```
A
B
C
```

---

## 2. 执行期间不会被其他客户端插入

类似隔离。

---

但是：

Redis没有完整ACID。

---

# 四、Redis事务和ACID区别

||Redis事务|MySQL ACID事务|
|---|---|---|
|原子性|弱|强|
|失败回滚|❌没有|✅有|
|隔离性|基本有|有|
|一致性|需要业务保证|数据库保证|
|持久性|看RDB/AOF|redo log保证|

---

举例：

Redis：

```redis
MULTI

SET money 10000

DECRBY money 8000

INCR xxx

EXEC
```

如果：

```
INCR xxx失败
```

Redis不会：

撤销：

```
SET money 10000
DECRBY money 8000
```

已经执行的保留。

# 五、什么是Redis分布式事务？

这里容易误解。

Redis本身并没有：

> Redis分布式事务

这种东西。

通常说的Redis分布式事务，是指：

## 多个系统之间的一致性问题

例如：

电商订单：

涉及：

```
订单服务(MySQL)

库存服务(Redis)

积分服务(MySQL)

支付服务
```

用户付款：

需要：

1. 创建订单
    
2. 扣库存
    
3. 扣余额
    
4. 增加积分
    

问题：

执行：

```
订单成功
库存扣了
支付失败
```

怎么办？

这就是：

## 分布式事务问题

---

# 六、分布式事务为什么难？

因为：

多个机器：

```
订单数据库

        |
        |
库存Redis

        |
        |
支付数据库
```

每个地方：

都有自己的事务。

但是：

没有一个统一事务。

---

# 七、分布式事务解决方案

## 1. 两阶段提交 2PC

流程：

第一阶段：

询问：

```
库存服务：
可以提交吗？

支付服务：
可以提交吗？
```

第二阶段：

统一：

```
commit
```

或者：

```
rollback
```

缺点：

性能差。

容易阻塞。

---

## 2. TCC

Try：

预留资源。

Confirm：

确认。

Cancel：

取消。

例如：

扣库存：

Try：

```
冻结库存10个
```

Confirm：

```
真正扣除
```

Cancel：

```
释放冻结
```

---

## 3. 消息最终一致性

现在互联网最常用。

例如：

支付：

```
订单服务
 |
发送消息
 |
MQ
 |
库存服务
```

失败：

重试。

最终：

达到一致。

---

# 八、Redis在分布式事务里面干什么？

Redis一般不是承担事务核心。

常见作用：

---

## 1. 分布式锁

例如：

抢订单：

```redis
SET order_lock user1 NX EX 10
```

保证：

只有一个服务操作。

---

## 2. 状态记录

例如：

订单状态：

```
UNPAY

PAYING

SUCCESS
```

存Redis：

快速查询。

---

## 3. 幂等控制

防止重复支付。

例如：

支付请求：

第一次：

```
payment:123=success
```

第二次：

发现存在：

直接返回。

---

# 九、和你之前余额扣减问题联系

你之前问：

三个线程：

```
余额10000

扣8000
扣4000
扣1000
```

Redis不能靠：

```
MULTI
```

解决。

因为：

MULTI：

不能保证：

```
查询余额
+
判断余额
+
扣钱
```

这个业务逻辑原子。

应该：

### Redis Lua：

```lua
if balance >= money
then
    balance=balance-money
end
```

或者：

### MySQL事务：

```sql
begin;

select balance
for update;


update balance;


commit;
```

# 十、最后总结

可以这样记：

```
ACID事务
    |
    |-- 单数据库内部一致性
    |
    |-- MySQL


Redis事务
    |
    |-- Redis内部命令批量执行
    |
    |-- 没有回滚


分布式事务
    |
    |-- 多服务、多数据库一致性
    |
    |-- 2PC/TCC/MQ最终一致性
```

面试回答：

> Redis事务通过MULTI、EXEC保证多个命令顺序执行和隔离性，但不具备传统数据库ACID事务的完整能力，没有回滚机制。分布式事务解决的是多个服务或数据库之间的数据一致性问题，常用方案包括2PC、TCC、消息最终一致性等。Redis通常作为缓存、锁、状态管理组件参与分布式事务，而不是作为核心事务数据库。
