**Redis怎么解决并发竞争问题（Race Condition）**

比如，三个线程同时操作一个账户，如果有10000，分别取8000，4000,1000都通过了，但是账户最后还变成-3000，这种情况怎么处理的？

1. 原子命令：Redis单线程执行Lua脚本，一个线程执行，别的线程插不进来

**持久化策略RDB AOF**

从最后一次成功生成RDB快照开始，到Redis宕机之间发生的数据修改，如果没有AOF记录，就可能丢失。

Redis 的持久化主要有两种：

1. **RDB（Redis Database）快照**： 定期拍照，把内存数据保存下来。
2. **AOF（Append Only File）追加日志**：记录每一次写操作，重启时重新执行这些操作。

RDB：定期fork主进程，来执行写操作，主进程不影响正常工作，保存到dump.rdb文件



## 为什么fork后数据不会乱？

使用：

## Copy On Write（写时复制）

例如：

原来：

```
money=10000
```

fork之后：

父进程：

```
money=10000
```

子进程：

```
money=10000
```

如果客户端修改：

```
SET money 5000
```

父进程复制一份：

```
父：

money=5000


子：

money=10000
```

所以RDB保存的是某一个时间点的数据。

---

## RDB优点

### 快

因为：

一次性写文件。

例如：

```
100万个key

一次保存
```

恢复：

直接加载：

```
dump.rdb
↓
内存
```

速度快。

## 缺点

会丢数据。

例如：

配置：

```

```

表示：

900秒内至少1次修改才保存。

如果：

10:00

保存RDB

10:05

服务器宕机

中间：

```
5分钟数据丢失
```

# 二、AOF（追加日志）

## 思想

Redis每执行一个写命令：

记录下来。

例如：

客户端：

```redis
SET name mao
```

AOF：

记录：

```
SET name mao
```

然后：

```redis
INCR age
```

AOF：

```
SET name mao
INCR age
```

文件：

```
appendonly.aof
```

---

## AOF怎么恢复？

Redis启动：

读取：

```
appendonly.aof
```

然后：

重新执行：

```
SET name mao

INCR age
```

恢复数据。

类似：

MySQL binlog。

---

# 三、AOF写入流程

比如：

执行：

```redis
SET money 10000
```

流程：

```
客户端

  |
  v

Redis内存

  |
  v

AOF缓冲区

  |
  v

磁盘appendonly.aof
```

注意：

不是每次立即写磁盘。

Redis提供三种策略：

---

## 1. always

每次写：

```
命令
 ↓
磁盘
```

安全：

★★★★★

性能：

低

---

## 2. everysec（默认）

每秒刷一次：

```
命令

↓

内存AOF buffer

↓

后台线程

↓

磁盘
```

最多丢：

1秒数据。

性能和安全平衡。

---

## 3. no

交给操作系统决定。

速度最快。

但是：

风险最大。

# 四、RDB和AOF区别

|      | RDB      | AOF            |
| ---- | -------- | -------------- |
| 方式   | 数据快照     | 记录命令           |
| 文件   | dump.rdb | appendonly.aof |
| 恢复速度 | 快        | 慢              |
| 数据安全 | 低        | 高              |
| 文件大小 | 小        | 大              |
| 性能影响 | 小        | 稍大             |
| 适合   | 备份       | 高可靠            |

# 六、面试简单回答

如果面试问：

> Redis持久化怎么实现？

可以回答：

> Redis提供RDB和AOF两种持久化方式。RDB通过fork子进程生成内存快照文件dump.rdb，利用Copy On Write保证主线程继续处理请求；AOF通过记录每次写命令到appendonly.aof文件，Redis重启时重新执行这些命令恢复数据。RDB恢复快但可能丢失部分数据，AOF数据安全性更高但文件更大，实际生产一般两者结合使用。

这就是 Redis 持久化的核心原理。
