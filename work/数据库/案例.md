


## 多对多查询

关联查询（又称多表查询或 JOIN 查询）是指，在数据库中，通过表与表之间的共同字段，把两个或多个表的数据连接起来进行统一查询的操作

内连接（交集），左连接（左为主，右没有为null），右连接，全连接（都为主，谁没有谁为null）


在“多对多”的关系下，关联查询不能直接查询吗？还需要新建立一个关联表吗？

**学生（Students）** 和 **课程（Courses）**。一个学生可以选多门课，一门课也可以被多个学生选，这是典型的**多对多**关系。

在学生表里加一个“课程ID”列，在课程表里加一个“学生ID”列类似，就按照学生表加课程为例，一个学生选了两个课及以上，那么做法要么是在课程id列，用逗号隔开，写多个课程，这要做模糊查询不方便（`LIKE '%1%'`），会导致**查询性能极差，索引失效**，而且容易误判（比如把ID为11的也查出来）。要么是直接新建一行除了课程id不一样，所有信息都一样，这会很冗余。

原因是，传统的二维关系型数据库，每一行里的每一个格子（字段）**只能存一个单一的值**，它天然装不下“多对多”的复杂关系。

解决办法，新建一个关联表，就俩字段，`Student_ID` 和 `Course_ID`，把一个抽象的“多对多”网状关系，**拆成了最简单的一行行独立的“一对一”映射**。想查小明选了什么课？用小明的 ID 去关联表里精准一拉，就得到了 101 和 102。想查数学有谁选？用数学的 ID 去关联表里一拉，就得到了小明和小红。

Student_ID (学生)        Course_ID (课程)   
1 (小明)                           101 (数学)    
1 (小明)                           102 (英语)        
2 (小红)                           101 (数学)     

学生表里，小明依然只有一行；课程表里，数学也依然只有一行。两张主表清清爽爽，数据绝不冗余。
可以在中间表的 `Student_ID` 和 `Course_ID` 上建立**索引**。这样哪怕有几百万条选课记录，数据库也能在几毫秒内完成关联，而不需要去一条条扫描字符串。

有了中间表后，你的关联查询其实就是把**三张表连成一条线**：
```
【学生表】 <== 内连接 ==> 【中间关联表】 <== 内连接 ==> 【课程表】

SELECT s.Name, c.Course_Name
FROM Students s
INNER JOIN Student_Courses sc ON s.Student_ID = sc.Student_ID
INNER JOIN Courses c ON sc.Course_ID = c.Course_ID;

SELECT s.Name, c.Course_Name      -- 第三步：只查询学生的姓名和课程名称
FROM Students s                   -- 第一步：从学生表开始，给表起个别名 s
INNER JOIN Student_Courses sc     -- 第二步：把学生表和选课中间表连接起来
ON s.Student_ID = sc.Student_ID   -- 连接条件：学生表的学号 = 中间表的学号
INNER JOIN Courses c              -- 第三步：再把上面的结果和课程表连接
ON sc.Course_ID = c.Course_ID;    -- 连接条件：中间表的课程号 = 课程表的课程号

```


没有索引：数据库查找 `Student_ID = 101` 的数据时，会从头到尾扫描整张表（全表扫描），一行一行比对。如果中间表有100万行，就要比对100万次。
**有了索引（B+树）**：数据库会构建一棵平衡树结构。查找时，它像用字典查字一样，从根节点开始，每次比较都跳过大量无关数据，直接定位到目标数据所在的物理位置。
